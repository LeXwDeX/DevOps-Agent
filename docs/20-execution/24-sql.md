# SQL 检验与执行

## 1. 适用范围（K-23）

| SQL 来源 | 检验方式 |
|---|---|
| 系统对项目目标库发出的 SQL（测试库操作、表格维护脚本、巡检） | 每次执行都走执行模型。 |
| 平台自身的固定 SQL（sqlc 生成、迁移文件） | 构建期分析和测试，随版本发布。迁移执行本身是一次受控执行。 |
| 第三方组件发出的固定 SQL（Grafana、Temporal 的内部存储；数据库 exporter 对目标库的固定只读查询，Q26） | 组件准入：固定版本、独立库或只读专用账号、查询集随版本审核；升级迁移作为一次受控执行。 |

## 2. 解析与分类

- 按目标数据库的产品、方言和版本选择解析器。数据库类型适配见 [云服务商](../30-features/35-cloud-providers.md) 的数据库派生层。
- 多语句脚本逐条解析，每条都要覆盖。
- 解析结果给出：语句类别（查询 / 数据变更 / 结构变更 / 权限）、涉及对象、条件是否存在。
- 分类结果用来套用读写分区策略（K-07）。
- 运行中拼接的 SQL、存储过程和函数内语句，无法确定实际内容时，视为"读写类别无法确定"，转人工。
- 方言不支持或解析失败：转人工（默认，见 Q7）。

候选解析器：PostgreSQL 用 pg_query_go，MySQL 系用 TiDB parser。见 [Go 技术选型](../50-engineering/51-go-stack.md)。语法树只说明结构，不能证明权限或影响范围。

## 3. SQL 的执行预期

| 字段 | SQL 中的写法 |
|---|---|
| 目标 | 数据库实例稳定 ID、库、schema |
| 读写类别 | 来自解析分类 |
| 预期变更 | 涉及的表、条件、预计影响行数 |
| 原生预演 | 适配器声明支持时，用不带 ANALYZE 的 `EXPLAIN` 取执行计划和估算行数；或在事务中计数 `SELECT count(*) ... WHERE <同条件>` |
| 可逆性 | 结构变更（DROP、ALTER）和无备份的删除视为不可逆 |
| 成功判据 | 实际影响行数在预期范围内 |

`EXPLAIN ANALYZE` 会真实执行语句，不能当预演。

## 4. 指纹

- 目标表的结构摘要。
- 影响条件下的行数（或校验和）。
- 执行前重算，不一致就退回（K-04）。

## 5. dcg 的 SQL 规则

dcg 规则包至少覆盖：`DROP`、`TRUNCATE`、不带 `WHERE` 的 `DELETE` / `UPDATE`、`GRANT` / `REVOKE`、修改用户和密码。命中转人工（K-08）。

## 6. Bash 调用 SQL

- 例如 `mysql -e "..."`、`psql -f file.sql`。
- 解析器从命令中提取 SQL，Bash 和 SQL 两部分都要检验。
- 提取不到完整 SQL（变量拼接、外部文件未登记）时，转人工。

## 7. 执行

- SQL 执行器只执行冻结后的语句和参数。
- 数据库凭证由执行器按 K 注入，Agent 看不到（K-16）。
- 查询结果经过 mask 后返回，并限制行数和大小。
- 不对 SQL 自动重试。结果未知时先查询实际状态（K-05）。

## 8. 测试库操作

用户按具体需求操作已登记的项目测试库：查询、插入、更新、删除、建表、改表、删表。每条都走本文流程。生产库是否允许写入，由该数据库的策略决定（建议生产写入区设为人工）。
