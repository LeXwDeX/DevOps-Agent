# 工具包装与登记

## 1. 三种包装形式

运维 API、Docker、文件操作、密钥使用等能力，一律包装成下面三种之一，再登记：

| 形式 | 适合 | 说明 |
|---|---|---|
| Bash 脚本 | 主机上的命令组合 | 内容固定，参数从 schema 代入。 |
| Python 脚本 | 需要解析、计算、调 SDK 的逻辑 | 内容固定，依赖固定版本。 |
| tool call | 结构化接口，例如云 API、Docker API、文件读写 | Go 内建工具，或 HTTP / RPC / MCP 适配器。 |

命令模板（见 [既定任务](23-harness-tasks.md)）是 Bash 形式里最小的一种。

## 2. 工具 schema 必须声明的字段

| 字段 | 说明 |
|---|---|
| 身份 | 命名空间、名称、版本、内容摘要、形式（Bash / Python / tool call） |
| 输入 / 输出 schema | 类型、必填、范围；输出的结构化字段 |
| 功能列表 | 一个工具可以有多个功能，例如云 provider 的每个 API |
| 读写分区 | 每个功能属于只读区还是写入区；是否计费、是否不可逆 |
| 原生预演 | 有没有；怎么调用 |
| 指纹方法 | 对哪类目标、取哪些字段 |
| 执行预期模板 | 参数代入后生成执行预期 |
| 默认策略 | 每个功能的默认模式（自动 / 人工 / 禁止）和 `allow_auto` |
| 需要的密钥 | K 列表和注入的环境变量名 |
| 目标类型 | 主机、容器、数据库、云资源、文件 |
| 运行限制 | 超时、并发、输出大小 |
| 幂等与恢复 | 是否幂等；结果未知时如何查询实际状态 |

工具自带的"只读""幂等"等描述（包括 MCP annotations）只是提示，系统按登记时的声明和验证结果为准。

## 3. 各类能力的包装

| 能力 | 包装 | 要点 |
|---|---|---|
| 云 API | tool call，每个 provider 一个适配器 | 每个 API 是一个功能，单独配置读写分区和策略。见 [云服务商](../30-features/35-cloud-providers.md)。 |
| Docker | tool call，由执行器调用目标主机的 Docker Engine | Agent 不持有 Docker socket。底座的节点代理只管理平台自身容器，不用于项目容器。 |
| 文件操作 | tool call 或脚本 | 读、写、上传、下载。写入限定在登记的根目录内，防止路径逃逸。读取"含密钥文件"转人工。 |
| 数据库 | SQL 执行器 | 见 [SQL](24-sql.md)。 |
| 系统服务 | 命令模板或脚本 | 启停、注册服务；重启可走预授权。 |
| 密钥 | 不提供给 Agent 的工具 | K 的增删改只由人工完成，见 [密钥](25-secrets.md)。 |
| 知识检索、摘要 | 内建只读工具 | 只读，不接触目标资产。 |

## 4. 登记规则

- 只有管理员（首版即用户）能登记、升级和停用工具（K-20）。
- Agent 可以起草工具 schema 和脚本，提交给用户审核。
- 远端发现（例如 MCP 服务器新增工具）只产生候选，审核登记后才能用。
- 同名工具拒绝重复登记；内容或 schema 变化建立新版本（K-21）。
- 调用绑定登记时的版本和摘要。

## 5. 统一调用路径

所有工具调用（内建、外部、MCP、子 Agent 发起、Hook 发起）都通过同一个入口提交给 Harness，走同一条执行路径。没有 Harness 时，所有工具执行关闭，只保留对话和计划。
