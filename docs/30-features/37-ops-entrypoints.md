# 运维入口与发起方式

## 1. 入口

| 入口 | 用途 | 约束 |
|---|---|---|
| 项目工作台 | 项目对话、部署、测试库操作、云资源、定时任务、审核、审计查询、运维表格、事实地图 | 绑定项目和环境。所有执行走 Harness。密钥只显示 K。 |
| 平台管理 | 登录、策略、登记资产、模型配置、K 管理、mask 规则、审计页面 | 见 [平台管理](38-platform-admin.md)。 |
| 底座管理 | VM 登记、平台容器部署、日志、健康和恢复 | 独立入口，运行在核心容器外。见 [部署底座](../10-architecture/12-deployment-substrate.md)。 |
| 人类直连终端 | 人工逐条执行命令 | 见第 3 节。 |
| IM 与告警回调 | 接收消息、告警，发起诊断任务；可在 IM 中处理审核 | 需鉴权、去重，映射到受控任务。IM 账号映射到平台身份。 |

## 2. 发起方式

| 方式 | 说明 | 审核 |
|---|---|---|
| 人工 | 用户在工作台或 IM 中发起 | 按会话模式和策略 |
| 定时 | 持久调度服务按计划触发既定任务 | 已登记任务按策略，默认自动 |
| 告警 | 监控旁路异步提交诊断任务；Agent 分析后提出建议或申请 | 修复动作按策略；告警本身不授予执行权 |
| 预授权 | 已登记的自愈动作或服务重启 | 预授权范围内自动（K-11） |

四种方式共用同一执行路径（见 [执行模型](../20-execution/21-execution-model.md)）。发起方式不改变策略和转人工条件。

检查失败不会自动扩大为修复。修复要么是预授权范围内的动作，要么是新的执行申请。

## 3. 人类直连终端（Q6 默认）

用户是可信的，但同样需要避免手误。默认形式：

- 逐条提交命令，不支持交互式会话（vim、top、less、交互式 psql 等）。
- 每条命令经过 dcg。命中时要求用户二次确认，不阻断。
- 执行前不要求写执行预期。
- 目标、命令、输出（mask 后）全量写入审计。
- 密钥同样只能用 K，由执行器注入。

## 4. 系统内不设破窗通道（K-26）

- 平台不提供绕过检验的应急入口。
- 核心系统、Harness 或执行器不可用时，真正的应急访问走系统外流程（例如直接登录主机）。
- 事后补登记：在工作台记录做了什么、在哪个目标、什么时间。受影响目标在事实地图中标为"待核验"，等待重新采集。
- 监控旁路在此期间继续工作。
