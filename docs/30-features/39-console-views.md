# 侧边栏与主要页面

侧边栏有四个主要入口，点击进入对应页面。这是第一版的页面范围，先做出来，再按使用情况优化。三个页面都绑定当前项目和环境，查询遵守项目和环境的访问范围。

| 入口 | 看什么 | 数据来源 |
|---|---|---|
| 运维大盘 | 现在有什么要我处理、什么出了问题、平台自己好不好 | Harness、监控旁路、事实地图、平台健康 |
| 逻辑拓扑地图 | 哪个 APP 和哪个 APP 有通信 | [事实地图](33-fact-map.md) |
| 当前资源 | 有哪些虚拟机，每台上面跑着哪些 APP | [事实地图](33-fact-map.md) |
| Harness 流程 | 已登记的 SOP（既定任务、规程包）列表、详情、版本和运行记录 | [Harness 与既定任务](../20-execution/23-harness-tasks.md) |

页面只读。任何改动都要通过对话让 Agent 起草，再走登记或执行流程。

## 0. 运维大盘

首页。按从上到下的顺序：

| 区块 | 内容 |
|---|---|
| 顶栏 | 当前项目和环境、会话模式；core、runtime、PostgreSQL、监控旁路、dcg、模型可用性的健康状态；事实最近采集时间 |
| 指标卡 | 待我处理、运行中任务、今日异常运行（与预期不符、失败、结果未知）、活跃告警 |
| 待我处理 | 待人工审核（▶ 执行、✕ 拒绝、点评）、等待输入（缺 K）、结果未知需核对。排在最前 |
| 告警 | 来自监控旁路的活跃告警，附严重程度、时间和关联的诊断任务 |
| 今日 SOP 运行 | 每次运行的 SOP、版本、触发方式、状态和停在哪一步 |
| 定时计划 | 正常、暂停（含恢复后暂停）、漏跑次数；可一键恢复计划 |
| 资源健康 | 按虚拟机显示运行、异常、未知；未知不算停机 |
| 拓扑异常 | 证据冲突、过期或仅有候选的通信关系 |
| 预授权 | 各预授权的使用次数、上限和有效期 |

规则：

- 大盘只读。能点的只有本来就需要人做的动作：▶ 执行、✕ 拒绝、点评、新增 K、核对结果、恢复计划。其他操作通过对话发起。
- 每个数字都能点进对应页面看明细和来源。
- 大盘在 core 容器里，core 停机时看不到。此时告警依靠监控旁路自己的通知和 Grafana（K-25）。

## 1. 逻辑拓扑地图

### 1.1 显示什么

- 节点：逻辑应用（app_id）。可以按环境、供应商、宿主、应用分组筛选。
- 连线：应用 A 调用应用 B 的 API，有方向。
- 每条连线都标明证据类型，三类分开显示，不合并成一个结论（K-27）：

| 证据类型 | 线型（示意） | 含义 |
|---|---|---|
| 实际观测 | 实线 | API 日志或调用链中看到了调用 |
| 配置声明 | 虚线 | 配置里写了依赖，不证明真的有调用 |
| 网络策略 | 点线 | 网络规则允许连通，不证明真的有调用 |
| 候选 | 灰色虚线 | 模型推测、尚未核验的关系 |

- 同一对应用之间有多类证据时，分别画出或在连线详情里分别列出。
- 过期、冲突或未知的关系有明显标记。缺少观测不等于"没有依赖"。

### 1.2 交互

- 点击节点：查看应用信息、运行实例、所在宿主，可跳到"当前资源"。
- 点击连线：查看证据、观测时间窗口、覆盖范围和事实版本。
- 选中一个 APP，可沿有证据的调用关系查看上游和下游。
- 在对话中问 Agent"某个 APP 依赖谁"，回答和地图用同一份事实，并带来源和时间。

### 1.3 数据契约与渲染

- 核心控制服务把事实转换成版本化的 JSON 结构 `TopologyView`，前端只认这份 JSON。
- `TopologyView` 是平台契约，用 schema 固定（K-22），至少包含：

| 部分 | 字段（示意） |
|---|---|
| 头部 | schema 版本、项目、环境、生成时间、所用事实版本、筛选条件 |
| 节点 | 稳定 ID、类型（应用）、名称、分组、状态、核验状态 |
| 连线 | 稳定 ID、源节点、目标节点、方向、证据类型、证据引用、观测时间窗口、核验状态 |

- 前端用 [Cytoscape.js](https://js.cytoscape.org/) 渲染：它直接读 JSON，支持分层布局、缩放、点击和按属性改变线型。
- 渲染库放在前端的适配层后面。以后换库只改适配层，`TopologyView` 不变。
- 地图由事实生成，不由 Agent 生成。Agent 推测的关系只能作为"候选"写入事实库，再显示出来。

## 2. 当前资源

### 2.1 默认视图：虚拟机模式

- 列出项目当前环境下的宿主（云主机、虚拟机）：稳定 ID、名称、供应商、区域、状态、规格、采集时间。
- 每台虚拟机可以展开，看到运行在上面的应用实例（进程、容器）：所属 APP、版本、端口、健康状态、启动方式（例如 systemd）。
- 每个字段显示来源和采集时间。未知就显示未知，缺测不显示成停机或 0（K-05）。

### 2.2 交互

- 点击 APP 实例：跳到拓扑地图并选中该 APP。
- 点击虚拟机：查看配置、网络和关联的告警。
- 需要操作资源（重启、扩容等）时，在对话中让 Agent 发起，走执行模型。页面上不提供直接操作按钮。

### 2.3 与运维表格的区别

| | 当前资源 | 运维表格 |
|---|---|---|
| 数据 | 事实地图里的实时事实 | 固定脚本按自然日维护的记录 |
| 用途 | 看现在是什么样 | 按需求统计和留存日快照 |
| 字段 | 固定的资源字段 | 用户自定义字段 |

## 3. Harness 流程（SOP）

### 3.1 列表

列表里每一项是一个已登记的 SOP（既定任务或规程包），显示：

- 名称、用途、适用环境。
- 当前启用版本、版本总数、最后修改时间。
- 最近一次运行的状态和时间。
- 关联的定时计划。

### 3.2 详情

点击某一项进入详情：

- 当前启用版本的步骤、分支条件、参数 schema、默认策略和补偿步骤（用流程图展示）。
- 版本历史：每个版本的登记时间、变更说明、审核记录；可以比较任意两个版本的差异。
- 运行记录：每次运行用的版本、触发方式、各步骤状态和结果。

### 3.3 和 Agent 对话修改 SOP

1. 在详情页打开对话，说明要怎么改。
2. Agent 读取当前启用版本，必要时检索历史版本，起草新版本，并给出与当前版本的差异。
3. 你在审核界面查看差异，点 ▶ 登记，或点评让 Agent 修改。
4. 登记后成为新版本。是否立即启用，在登记时一起确认。

Agent 只能起草，不能登记或启用（K-20）。

### 3.4 版本与回滚

版本规则见 [Harness 与既定任务](../20-execution/23-harness-tasks.md) 第 2.7 节。页面上的操作：

- "设为当前版本"：选择历史中的某个版本作为当前启用版本，就是回滚（或前滚）。需要你点 ▶ 确认，记入审计。
- 历史版本只能查看和比较，不能修改或删除。

### 3.5 Agent 检索历史版本

Agent 有三个只读工具：

| 工具 | 作用 |
|---|---|
| 列出版本 | 返回某个 SOP 的全部版本、登记时间、变更说明、哪个是当前启用版本 |
| 读取版本 | 返回某个版本的完整内容 |
| 比较版本 | 返回两个版本的差异 |

这些工具只读、不接触目标资产，按 Q16 的默认可免自审。
