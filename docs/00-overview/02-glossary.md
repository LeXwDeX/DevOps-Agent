# 术语表

## 执行与审核

| 术语 | 含义 | 旧称 / 备注 |
|---|---|---|
| 检验阶段 / 执行阶段 | 先检验，再执行（K-01）。检验阶段只观察不改变（K-02）。 | |
| 执行预期 | 执行前写出的结构化预期：目标、读写类别、改变什么、预期结果、能否回退、成功判据。 | 用户说的 DRY-RUN 指的就是它。旧稿把 DRY-RUN 定义为"真实无副作用预演"，已废弃。 |
| 原生预演 | 工具自带的预览能力，例如 `terraform plan`、`kubectl --dry-run=server`、`apt -s`、`rsync -n`、云 API 的 DryRun、不带 ANALYZE 的 `EXPLAIN`。有就必须跑，结果附在执行预期里。 | |
| 状态指纹 | 检验时对目标状态取的摘要。执行前重算比对，不一致就不执行（K-04）。 | 不是锁。 |
| 模型自审 | 主模型在提交前，对自己的最终内容和执行预期再确认一次，给出"无风险 / 有风险及原因"。 | |
| dcg | 外部确定性命令守卫，选用 [destructive_command_guard](https://github.com/Dicklesworthstone/destructive_command_guard)。按规则包识别破坏性命令和 SQL，命中就转人工，平台策略标为禁止的直接拒绝。 | 旧稿写作 DCG，未展开。 |
| 策略 | 决定一次执行是自动、人工还是禁止的配置。按功能 > 权限区 > 全局 > 系统兜底生效（K-07）。 | 策略结果只写"自动 / 人工 / 禁止"（auto / manual / forbid）。 |
| 会话模式 | 会话级开关：手工模式（未预授权的执行都要人工点）或自动模式（按策略）。 | 类似 Claude Code / Codex 的审批模式。只有会话模式用"手工"一词，策略结果用"人工"。 |
| 权限区 | 工具功能按读写影响分成只读区和写入区，用于套用策略。 | |
| 人工审核 | 审核界面上的 ▶ 执行、✕ 拒绝、点评三个动作（K-09）。 | |
| 预授权 | 对重复且相同的动作一次审核、长期使用的授权（K-11）。 | |
| 独立审核模型 | 可选配置的另一个模型，给出附加风险意见（K-12）。 | 旧称 JEV、审核子 Agent。不再强制。 |
| 注入内容 | 外部内容里出现、试图让 Agent 执行的指令（K-19）。 | |

## 执行对象

| 术语 | 含义 | 旧称 / 备注 |
|---|---|---|
| 执行申请 | 一次执行的完整记录：CallID、Revision、内容、目标、执行预期、指纹、自审、dcg、策略、审核和结果。 | |
| CallID / Revision | 一次调用的稳定编号 / 修订号（K-13）。 | 旧稿也写 logicalCallID。 |
| 受控改写 | Harness 把修订写入待执行内容的唯一入口（K-14）。 | ControlledRewrite |
| 冻结 | 最终修订通过检验后固定，不能再改（K-15）。 | 旧稿的"已审计"标记，指冻结后的状态。 |
| 独立命令 | Agent 临时组合、未登记的命令。首版只能人工执行（K-10）。 | 自由 Bash |
| 命令模板 | 已登记的参数化命令，带参数语法、读写分类、预期模板和指纹方法。 | |
| 既定任务 | Harness 按登记的步骤和分支条件运行的任务，例如执行 A→B→C→D，按 D 的结果走 E→F→G 或 H→L→M。 | |
| 规程包 | 一组已登记的既定任务、参数 schema、说明和恢复步骤，用于某类工作（例如项目部署）。 | 旧稿称"类似 SKILL 的规程包"。 |

## 组件

| 术语 | 含义 | 旧称 / 备注 |
|---|---|---|
| core 容器 | 首版两个应用容器之一，运行核心控制服务和 Agent Worker 两个进程，不持有资产凭证和模型 key。 | 核心容器、控制面 |
| runtime 容器 | 首版两个应用容器之一，运行 Harness、持久调度服务、执行器、模型出口代理，持有凭证库。 | |
| 挂载表 | 部署契约：每个容器挂哪些外部目录、只读还是读写、属主权限、是否备份（K-31）。 | |
| Agent Worker | core 容器内的独立进程，嵌入 GoAgent SDK，运行模型任务。不持有凭证（K-18）。 | |
| Harness | 两项职责：①执行门禁（执行预期、指纹、自审结论、dcg、策略、人工审核）；②既定任务编排。位于核心容器外。 | |
| 执行器 | 持有凭证、真正操作目标的进程。只执行已冻结的内容。 | 执行面 |
| 持久调度服务 | 按时间表达式和项目自然日提交执行申请的服务。 | 旧稿混用"独立持久调度器""独立调度执行服务"，统一为此名。 |
| 监控旁路 | 独立的采集、规则、告警和通知链路（K-25）。 | |
| 核心控制服务 | core 容器内的 Go 控制服务进程。 | |
| 模型出口代理 | 注入模型 API key、限制模型出口端点的组件。它实现 SDK 的鉴权传输端口（AuthenticatedTransportPort）。 | 旧稿称"宿主鉴权传输后端" |
| 底座 | Supervisor 托管的底座控制服务和节点代理，用于部署平台自身。 | Docker 部署底座 |
| 底座控制服务 | 底座的管理服务：VM 清单、部署模板、平台部署申请。 | 旧称"平台控制服务"。与核心控制服务无关。 |
| 节点代理 | 底座在每台 VM 上的进程，只调用本机 Docker Engine 管理平台自身容器。 | 旧称"节点执行器"。与执行器无关，不操作项目资产。 |
| 底座管理入口 | 底座控制服务提供的管理员入口，运行在核心外，核心停机时也可用。 | 与平台管理模块不同：后者在核心内。 |
| 部署包 | 平台组件的固定镜像摘要、版本化配置和状态存储映射。 | 用于部署平台自身，与项目的规程包不同。 |
| 受控环境模板 | 部署平台组件时使用的目标身份、运行时、资源、网络、凭证引用和持久化约束。 | |
| 出厂资产包 | 平台自带的 dcg 规则包、内置 mask 规则、内置命令模板等的固定版本。导入后仍需登记（K-20）。 | |
| 发布清单 | 一次发布固定的平台、SDK、schema、迁移、出厂资产包等版本组合。 | |
| Worker | 单说 Worker 时，指 Agent Worker。监控模块 Worker、Temporal Worker 必须写全称。 | |
| 事实地图 | 结构化事实库及其视图，记录资产、关系和证据。 | 运维事实地图 |
| 运维表格 | 由已登记脚本维护的通用结构化表格。 | |
| 平台管理模块 | 身份、登录、SSO、MFA、策略、登记、模型配置、审计页面等管理功能。首版单人使用，结构预留。 | |

## 密钥

| 术语 | 含义 | 旧称 / 备注 |
|---|---|---|
| K / V | K 是密钥的引用名，V 是密钥值。模型只传 K（K-16）。 | 旧称"密钥剪贴板"，已废弃。 |
| 凭证库 | 保存 V 的受控后端。只能增、删、改，不能读出。 | |
| mask 规则 | 识别并遮盖密钥的规则，含内置规则和人工规则（K-17）。 | |
| 脱敏 | 字段白名单过滤加 mask。用于事件、日志、Hook 输入和审计。 | 单指遮盖密钥值时用 mask。 |

## SDK

| 术语 | 含义 | 旧称 / 备注 |
|---|---|---|
| GoAgent SDK | 本项目独立、版本化的 Go Agent SDK。 | SDK |
| 宿主 | 嵌入 SDK 的程序。本平台的 Agent Worker 是一个宿主。 | |
| 第二宿主 | 用来证明 SDK 独立性的另一个宿主样例。 | |
| ModelProfile / ModelRole | 模型配置 / 模型职责角色。 | |
| 厂商派生适配器 | GLM、DeepSeek 等，强制嵌入对应基础协议适配器，只重写差异。 | 旧称"厂商 PATCH" |
| 派生解析器 | 监控模块里按格式派生的解析器。 | 旧称"解析器 PATCH" |
| ContextPatch | 对上下文投影的版本化编辑。 | 与上面两种"派生"无关 |
| ExpectationDraft | SDK 中 Agent 写出的执行预期草稿，随工具申请提交。 | 对应执行预期 |
| SelfReview | SDK 中的模型自审结论：无风险 / 有风险及原因。Harness 只把它当输入。 | 对应模型自审 |
| ToolRequestStatus | SDK 侧的工具申请状态，与平台执行申请状态一一对应（K-22）。 | |
| HookDecision | Before Hook 的返回：Continue、Pause、Reject、Patch、Restrict（只能收紧条件，例如要求人工）、Opinion（修订意见，只交给 Agent 自审参考，不是修订来源）。 | |
| 分派器 | SDK 和监控框架中，按接口调用派生适配器或派生解析器的固定代码。 | 旧稿称"固定调度器"。与持久调度服务无关。 |
| Hook | 宿主固定登记的扩展函数：观察 Hook 和 Before Hook。 | |
| EventType | 公开事件类型的字符串常量。SDK 用 `goagent.*`，平台用 `devops.*`。 | |

## 其他

| 术语 | 含义 |
|---|---|
| 项目 | 业务归属和工作范围。不等于部署单位。 |
| 环境 | 项目下的 dev、test、prod 等目标范围。策略可按环境区分。 |
| 稳定 ID | 资产的唯一身份，绑定项目、云账号、区域和环境。名称和 IP 只是属性。 |
| 组件准入 | 第三方组件的一次性准入审核，替代对其内部 SQL 的逐次检验（K-23）。 |
| Hermes | 设计参考，不是部署组件、依赖或兼容目标。 |
