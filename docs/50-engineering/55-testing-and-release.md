# 复测与发布

## 1. 原则

- 测试要证明门禁有效，而不只是功能能用。负例和正例同样重要。
- 门禁测试用固定输入和重放的模型响应，结果确定。模型行为评估另做，不能用"模型回答正确"代替门禁测试。
- 每阶段累积复测（K-29）。已交付的安全关键路径每阶段都重跑。
- 缺少关键测试时，不能宣称该能力可用。

## 2. 检查时点

| 时点 | 必须证明的内容 |
|---|---|
| 每次变更 | `gofmt`、`go vet`、相关 `go test`；受影响并发路径跑 race；`govulncheck`；依赖方向检查（[53](53-repo-layout.md) 第 5 节）；生成代码与定义一致、文档枚举与代码常量一致（[52](52-schema-and-constants.md) 第 6.2 节）；登记资产按 schema 校验；SDK 样例和旧调用方可编译；重放固定模型响应验证确定性路径；fuzz 种子语料。 |
| 每阶段复测 | 第 3 节全部门禁负例；真实目标版本的 SQL 解析与执行；CAS 冲突；审计和凭证隔离；取消；断点崩溃注入（第 4 节）；恢复即停止。 |
| 解析与输入边界 | 对 SQL 输入、执行申请内容摘要的规范化、JSON/XML/二进制解析、派生解析器匹配、命令模板参数语法、分支条件表达式、mask 规则做 fuzz。每次变更跑种子语料；阶段复测和发布按固定预算扩展。无效、超限、冲突和无法覆盖的输入，结果必须是拒绝、转人工或未知。 |
| 服务与版本兼容 | 在固定版本的真实 PostgreSQL、MySQL、Docker API 和已声明的云产品上检验适配器。验证 CGO 目标镜像和两种 CPU 架构。按支持范围检验新旧 SDK、接口、schema、规程和在途任务版本，而不是只检验最新组合。 |
| 升级与回退 | 数据库按"先扩展兼容结构 → 迁移数据 → 最后收缩旧结构"。旧调用方和在途任务退出前不删除旧契约。升级中断、备份恢复、镜像回退和远端实际状态核验分别测试。镜像回退不等于数据库或云操作回滚。升级会触发恢复即停止，要验证恢复报告正确。 |
| 发布 | 第 6 节的发布门槛。 |

## 3. 门禁负例清单（累积）

每阶段复测都跑。新阶段只能追加，不能删除。

| 用例 | 期望结果 | 依据 |
|---|---|---|
| 没有 Harness 时发起工具请求 | 执行次数为零 | [26](../20-execution/26-tool-wrapping.md) 第 5 节 |
| SDK 或核心传来"已批准"标记 | 被忽略，照常检验 | [22](../20-execution/22-review-and-policy.md) 第 2.1 节 |
| 缺少自审结论 | 按"有风险"转人工 | 同上 |
| 执行前指纹与检验时不一致 | 不执行，状态"目标已变化"，不自动重试 | K-04 |
| 无法采集指纹 | 转人工 | K-08 |
| 读写类别无法确定 | 转人工 | K-08 |
| 不可逆且无原生预演 | 转人工 | K-08、Q3 |
| dcg 命中 | 不自动执行，转人工 | K-06、Q2 |
| dcg 规则标为禁止 | 直接拒绝 | K-08 |
| 策略为禁止 | 任何会话模式下执行次数为零 | K-08 |
| `allow_auto: false` 的功能被配成自动 | 配置被拒绝或按人工处理 | [22](../20-execution/22-review-and-policy.md) 第 4.2 节 |
| 人工批准后又修订 | 旧批准失效，从头检验；CallID 不变，Revision 加一 | K-09、K-13 |
| 冻结后尝试改内容 | 被拒绝 | K-15 |
| 执行器收到摘要不符的内容 | 不执行 | [11](../10-architecture/11-components-and-boundaries.md) 第 2 节 |
| Hook 或上下文补丁改工具内容 | 被拒绝 | K-14 |
| 独立命令在自动模式下 | 仍需人工 | K-10、Q1 |
| `EXPLAIN ANALYZE` 作为预演 | 不被接受 | [24](../20-execution/24-sql.md) 第 3 节 |
| SQL 方言不支持或解析失败 | 转人工 | Q7 |
| Bash 内嵌 SQL 提取不完整 | 转人工 | [24](../20-execution/24-sql.md) 第 6 节 |
| 命令内容里出现 V | 被拒绝 | [25](../20-execution/25-secrets.md) 第 3 节 |
| 执行输出含 V（例如 `echo $变量`） | 输出被 mask | K-17 |
| 任何接口尝试读取 V | 没有这样的接口 | K-16 |
| Agent 尝试登记工具或启用 Hook | 被拒绝 | K-20 |
| 外部内容里出现指令 | 不执行，上报疑似注入 | K-19 |
| 既定任务没有分支匹配 | 停止，转人工 | [23](../20-execution/23-harness-tasks.md) 第 2.3 节 |
| 步骤"与预期不符"或"结果未知" | 不进入任何分支，停止 | 同上 |
| 预授权内容摘要变化、超次数或过期 | 不执行，告警 | K-11 |
| 重启或恢复后 | 在途任务"已停止（恢复中断）"；执行中的"结果未知"；计划暂停；没有自动续跑 | K-24 |
| 同一调度周期重复触发 | 只提交一次 | [13](../10-architecture/13-state-and-recovery.md) 第 3 节 |
| 迟到的执行结果 | 不覆盖较新的记录 | 同上 |
| 重复投递的消息 | 不重复执行 | 同上 |
| 缺测或结果未知 | 显示为未知，不记成功、"否"或 0 | K-05 |
| 关闭核心和 Worker | 监控采集和告警继续 | K-25 |

## 4. 断点崩溃注入

在下列断点注入进程崩溃，验证恢复后的状态明确：

| 断点 | 恢复后期望 |
|---|---|
| 执行申请已保存，尚未冻结 | 已停止（恢复中断） |
| 已冻结，尚未开始执行 | 已停止（恢复中断）；不自动执行 |
| "开始执行"已落盘，执行器尚未调用目标 | 结果未知，等人工核对 |
| 目标已成功，本地尚未记录结果 | 结果未知，先查询目标实际状态 |
| 既定任务在两步之间 | 任务已停止，不从下一步续跑 |
| 调度周期已接受，尚未提交 | 计划暂停；恢复后同一周期键不重复提交 |
| 迁移执行中 | 结果未知；不自动重跑迁移 |

## 5. "不留技术债"的工程含义

- 不积累已知的设计和实现缺口。
- 每个可用模块同时交付：接口、实现、契约测试（含负例）、失败与恢复、资源与观测指标、迁移、文档和版本清单。
- 不用待办、默认放行或失效的测试占位代替实现。
- 这不表示未知缺陷永远不会出现。发现后按影响关闭相关能力，补齐复现和回归测试，再恢复发布。
- 赶进度时缩小范围、关闭入口，而不是降低门禁。

## 6. 发布门槛

| 类别 | 处理 |
|---|---|
| 已知安全缺陷 | 阻断发布 |
| 已知一致性缺陷（状态、结果、审计不一致） | 阻断发布 |
| 公共兼容破坏（SDK、服务协议、schema） | 阻断发布，或走主版本流程 |
| 审计缺失 | 阻断发布 |
| 恢复缺陷 | 阻断发布 |
| 其他已知工程缺口 | 合入前补齐；或移出本次交付范围并关闭入口 |

## 7. 版本管理

分别管理版本的对象：

| 对象 | 版本规则 |
|---|---|
| 平台 | 平台整体版本，对应一组镜像 digest |
| GoAgent SDK | Go 模块语义化版本。先 v0；P6 通过兼容与恢复验收后发布 v1。破坏性变更用新主版本和对应导入路径，不能用平台升级强迫其他宿主同步升级。 |
| 服务协议与 schema | 按 SchemaID 和版本（[52](52-schema-and-constants.md)） |
| 规程包、任务定义、命令模板、工具 schema | 登记版本和内容摘要（K-20、K-21） |
| dcg 规则包、mask 内置规则、策略 | 登记版本 |
| 解析器、派生适配器、云适配器 | 各自版本，登记父类型与派生版本 |
| 平台库迁移集 | 迁移版本 |

公共模块按 Go 发布流程发布。平台不能用本地 `replace` 掩盖 SDK 的对外依赖。

## 8. 发布清单

发布清单固定一次发布的兼容组合。

| 字段 | 内容 |
|---|---|
| 版本 | 平台版本、SDK 版本范围 |
| 镜像 | 每个组件的镜像 digest、构建镜像、Go 版本、目标架构 |
| 依赖 | 依赖清单、许可、维护状态、`govulncheck` 结果 |
| 定义 | schema 版本集合、迁移集版本、出厂资产包版本（dcg 规则包、mask 规则、内置模板） |
| 支持矩阵 | 数据库产品与版本、云产品与 API 版本、模型协议与厂商派生适配器、宿主系统与 Docker 运行时 |
| 测试证据 | 阶段复测结果、fuzz 预算与结果、race 结果、真实服务兼容结果 |
| 已知限制 | 未开放的能力及关闭方式 |
| 升级与回退 | 步骤、前置条件、数据库迁移方向、回退边界（镜像回退不回滚数据和远端操作） |

## 9. 扩展准入（通用部分）

适用于新增协议、模型 profile、厂商派生适配器、压缩器、工具适配器、云适配器、数据库派生类型和派生解析器。

| 要求 | 说明 |
|---|---|
| 版本清单与契约语料 | 随扩展一起提交。 |
| 派生关系 | 证明嵌入的父类型与版本；未重写的行为沿用父实现；重写通过最外层对象的接口分派生效；固定门禁未改变（K-28）。 |
| 协议语料 | 覆盖普通与流式回复、分片的工具参数、多工具关联、错误、取消、缺失用量（记为未知，不填 0）、截断、重复字段和未知字段。 |
| 未知字段 | 协议中的必要状态不能丢弃。未知可选字段只保存在审核过的 sidecar 结构中，不获得执行含义。 |
| 工具复测 | 恶意描述和 MCP annotations、版本变化、范围不足、审核拒绝、缺少执行预期、有原生预演却未运行、SQL 解析不完整、断流、执行后崩溃。 |
| 零执行断言 | 被拒绝的申请不新增执行；未提交的无效申请执行次数为零；结果不明时先查询实际状态或停止。 |
| 真实兼容 | 真实 API 兼容验收在独立的授权环境进行，通过范围写入支持矩阵。HTTP 请求成功不能证明协议能力全部兼容。 |
| 适配器能力 | 云和数据库适配器声明原生预演、幂等、状态查询和失败恢复能力；读写分区和默认策略。 |

SDK 专项回归另见：协议适配器准入语料见 [LLM 协议](../40-sdk/42-llm-protocols.md) 第 10 节，上下文复测见 [上下文管理](../40-sdk/43-context-management.md) 第 9 节，工具复测见 [SDK 工具目录](../40-sdk/44-tool-catalog.md) 第 11 节，事件与 Hook 回归见 [事件与 Hook](../40-sdk/45-events-and-hooks.md) 第 10 节，第二宿主验收见 [SDK 概览](../40-sdk/41-sdk-overview.md)。新宿主接入必须有兼容回归。
