00架构内核与设计哲学

先检验，再执行。

设计哲学作为架构内核，定义所有功能与流程必须遵守的共同约束。统一顺序是检验阶段 → 执行阶段。检验包括需求沟通、事实与权限核验、Bash DRY-RUN、SQL 语法分析、独立子 Agent 审核和适用人审。只有本次操作所需检验全部通过，执行面才可执行。

安全性与可靠性进入功能准入条件。设计项目对话、项目 Agent 生成、部署、脚本、SQL、云 API、Docker 底座、监控模块、定时任务、自动重启和密钥传递时，均须明确下列约束。Harness、固定规则与各执行器共同落实约束；派生适配器和 PATCH 只能扩展声明的业务接口。

共同约束功能与流程必须说明的内容
输入与事实项目、环境、稳定目标 ID、内容、参数、版本、证据来源和时效。未知、过期或冲突明确呈现，不能补成已确认事实。
权限与检验谁可发起、工具可访问什么、所需检验、通过条件与产物有效期。必需检验未通过时，相关操作不可执行；审批和模型判断不能豁免强制门禁。
执行与隔离执行器、固定内容、影响范围、资源限额和密钥注入方式。只执行与检验产物匹配的申请；凭证明文对所有 Agent 隔离。
成功与证据实际结果、健康判据和审计记录。已提交或已接受不等于完成；缺测和未知结果不能记为成功。
失败与恢复超时、有限重试、未知结果核验、补偿和恢复步骤。先核验现状，再对恢复操作先检验后执行；不能盲目重放。

新功能、规程、适配器和派生处理器在审核准入前须给出上述内容，未满足时保持不可用。已审核方法每次调用仍检验当前条件。监控旁路的固定采集与通知由独立服务执行配置、身份、输入和输出校验，不增加对在线 Agent 或模型的依赖；其中 Bash 和 SQL 继续满足各自强制门禁。

路径检验阶段执行阶段
人类与 Agent通过长沟通和必要提问，确认本次需求、项目事实、目标、权限、计划、输入和验收标准。保存确认记录、来源与待确认项。Agent 按已确认的计划和允许参数推进工作流。实际操作仍由执行面按对应申请检验后执行。
Agent 与 Bash / SQL 执行框架固定完整展开的命令或 SQL、参数、目标和影响范围。Bash 完成有效 DRY-RUN；SQL 按目标类型和版本完成完整语法分析。取得有效 JEV 裁决和所需人工授权。执行面最后核验本次申请与检验产物一致，仅执行相同内容、参数和目标。保存脱敏输出，检验实际结果并记录审计。

两条路径分别保存检验记录，并由 Harness 汇总到同一执行申请。检验结论绑定申请摘要、项目、目标、环境、内容、参数、事实、配置和方言版本。必需信息缺失、检验不通过或产物失效时，相关操作保持不可执行。

阶段按本次任务和步骤推进，与测试或生产环境、方法是否已登记分别记录。每次实际执行都先检验，包括复用已有规程、定时任务、试部署和试启动。有效产物只有在覆盖本次相同内容与作用域时才可复用，并须逐次核验有效性；内容或条件变化时重新检验。

检验阶段只使用受审核的分析和预演接口。DRY-RUN 保证不修改目标业务状态，SQL 分析不执行待检验的 SQL。需要实际效果验证时，试运行建立自己的申请，先完成所需检验和授权，再进入执行阶段，结果作为后续验收证据。

首次形成规程时通过多轮提问确定方法和参数范围，管理员审核并固定版本后登记。复用规程可以减少重复沟通；本次必需参数、人工密钥的引用与可用状态，以及执行授权仍须检验。规程外的变化建立新版本重新检验，不自动注册工具或 skill。

决策、授权与执行各有明确职责。

Agent 提交计划和执行申请。独立审核子 Agent 复核操作。控制面依据事实与规则完成校验。执行面持有资产凭证，并在 Harness 核验全部门禁后执行。

密钥隔离同属架构内核。密钥剪贴板属于 Agent 工具与全局变量体系，提供增、删、改和工具查。用户与所有 Agent 只使用编号、非敏感备注及操作状态。工具内部取用与写入也先检验，再执行。具体边界见密钥剪贴板。

核心容器承载项目接入、业务管理、会话与任务状态、工作流控制和事实查询。Agent Worker 在独立容器中处理模型任务。Harness、执行服务、独立审核子 Agent、部署管理权限及审计保存边界位于核心容器外。

采集、监控、规则计算和报警独立运行。Agent Worker、模型服务或核心容器不可用时，旁路继续保存数据和发送通知。

工具、MCP、skill 和项目部署规程包由管理员白名单管理。Agent 可按已确认的流程整理部署规程草稿。草稿只有经管理员审核、固定版本和登记后才可加载执行。自动注册工具或 skill、自动发布规程、自动改运行配置及自主学习机制不进入系统运行路径。

会话须受控创建，/new 是合法入口。工作流记录任务依赖、执行状态、失败与恢复过程。发起方式和子 agent 均继承执行权限与审计约束。

01项目工作台与用户流程

项目是业务归属和用户工作的统一范围。它独立于 DevOps-Agent 核心实例的部署单位。项目资料、真实环境事实、脚本版本、环境资产与数据库、定时任务、对话和执行记录都关联到项目。

项目会话与执行申请绑定项目和目标环境。切换项目或环境时，控制面重新核验成员权限、目标身份和当前事实，不能沿用上一个范围的授权。项目归属限定任务范围，不能代替环境授权、审批和执行门禁。项目对话提供上下文，执行仍由执行面完成。

所有 Agent 执行申请都由独立审核子 Agent 复核。Bash、脚本和命令必须先完成 DRY-RUN，并取得有效的通过结果；不支持 DRY-RUN 或缺少有效通过结果时禁止执行。每条 SQL 都须按目标数据库类型和版本进行语法分析；缺少分析结果或分析未通过时禁止执行。控制面与执行框架强制这些门禁，不能只依赖提示词。执行顺序见受控执行路径。

用户流程工作方式与边界
项目内问答用户在项目工作台中提问。Agent 查询项目资料和已核验的环境事实。回答显示来源与核验时间；模型推测保留为建议，不能写成已核验事实。
一键部署应用每次项目部署先进入检验阶段，确定本次规程版本、输入、目标、事实和授权。检验通过后，执行面按固定申请部署，最后核验健康并记录结果。首次形成规程时通过多轮沟通和受控试部署确定方法；每次试部署也先检验。新脚本由管理员审核并固定版本后才可执行。一键简化操作，不跳过门禁。Agent 不得自动注册工具或 skill。
CRONTAB 监控用户指定时间表达式、时区和已审核的检查任务。调度器只触发统一受控执行。系统保存检查结果、缺测和失败状态，并按规则通知。检查失败不能自动扩大为危险修复；修复仍走既有授权和人工审批。
测试库操作按具体需求操作已登记并核验的项目测试环境，支持查询、插入、更新、删除数据，以及建表、改表和删表。申请明确数据库、对象、操作条件、SQL 或脚本及影响范围。执行仍经过既有门禁；危险操作按规则由人审批，数据库凭证只在执行面使用。

部署项目应用属于项目任务，由执行面操作已授权的目标环境。部署 DevOps-Agent 平台自身属于 Docker 底座管理职责。底座平台不替代项目权限，也不向 Agent 开放宿主管理权限。

项目部署：检验 → 执行

项目部署沿用先检验，再执行的统一顺序。首次形成规程时，检验阶段通过长沟通和多轮提问确定做法；审核登记的规程可作为类似 SKILL 的复用资产。每次部署仍先检验本次版本、参数、目标、事实和授权，通过后才进入执行阶段。各步骤按自己的申请落实该顺序。

维度检验阶段执行阶段
目标明确需求和计划，检验方法、条件、权限、预期效果及失败处理。按检验通过的固定内容完成本次部署。
对话方式首次按步骤多轮询问，保存已答问题与待确认项。复用规程时重点确认本次参数和变化，必需信息缺失时补问。展示步骤状态和结果。需要人工密钥或新输入时暂停。密钥由人工直接填写到受控入口，Agent 只收到引用及可用状态；取得输入后重新检验受影响的步骤。
输入与事实按参数 schema 检验项目、环境、目标身份、制品、配置、密钥引用及当前事实，形成固定的执行清单。仅使用与本次检验产物匹配的输入。改变目录、内容、参数、配置或目标时停止相关执行并重新检验。
执行方式管理员审核脚本及适配器版本。JEV 初审后，受控接口完成 DRY-RUN 和所需 SQL 分析，随后 JEV 复核产物并取得适用人审。执行面最后核验全部条件，按已检验内容操作。试部署、试启动、权限设置及服务注册均属于执行。
主要产物需求确认、事实证据、固定申请、预检结果、JEV 裁决及适用审批。规程包审核和登记记录独立保存。本次部署的步骤状态、脱敏输出、实际健康结果、事实和审计记录。
差异与失败未通过时补充证据或修订申请，再检验；当前申请不可执行。失败后核验目标现状，按批准的恢复步骤先检验再执行。新增或超出范围的方法建立新版本重新检验。

进入执行阶段的条件

  1. 需求与目标检验通过。本次项目、环境、目标、方法、参数、权限和验收标准明确。必需的待确认项为空，关键事实有效且无冲突。
  2. 命令与 SQL 检验通过。本次 Bash、脚本及其他命令取得有效 DRY-RUN 结果。本次 SQL 按目标类型和版本完成完整语法分析。Bash 调用 SQL 时两项均通过。
  3. 审核与授权检验通过。有效 JEV 复核裁决与所需人审绑定同一申请。执行面最终核验目标、摘要、内容、参数、版本、预检和审批。任一条件失效时重新检验。

类似 SKILL 的项目部署规程包

规程包是可审核、可版本化的部署资产。它包含用途说明、适用范围、参数 schema、固定工作流、脚本及适配器引用、DRY-RUN 方法、所需 SQL 分析能力、人工输入点、健康判据、监控要求和恢复步骤。文字说明供 Agent 引导对话，执行面按结构化工作流和固定引用运行。

首次定版先检验流程和必需输入。候选脚本与适配器须先审核并固定版本，必要试部署建立自己的申请，在检验通过后执行。JEV 复核规程和验收证据，管理员审核范围、依赖、权限和失败处理，固定内容摘要并登记白名单。只有已审核资产才可作为复用规程加载执行。

包以 procedure_id、procedure_version 和内容摘要定位。登记记录保存包的审核及准入状态、适用范围、验证证据和批准引用。每次任务另行保存自己的检验阶段与执行阶段记录。真实执行、审核和问答记录保存在包外，以引用关联。密钥只保存引用，明文由人工通过受控入口填写。

固定的是部署方法和允许参数范围。后续按声明规则选择新制品版本时，本次制品、参数、目标、配置和授权仍先检验。规程批准不能代替本次 DRY-RUN、SQL 分析、JEV 裁决或人审。缺少受支持的预演或分析能力时，相关步骤保持不可执行。

方法变更：新版本重新检验

目录映射、INI 语义、启动定义、运行身份、适配器、检查标准或恢复方法超出原规则时，创建新版本草稿并重新检验。新格式和派生处理器也须审核。允许范围内的参数变化重新检验本次输入和门禁，规程包继续使用原版本。

新草稿继承现有规程和证据，只追问变化和未确定事项。旧已审核包在仍符合适用条件且未撤销时可供选用，但每次操作都先检验。发现包失效时暂停依赖它的新执行并报警。修订草稿不自动修改当前服务；服务变更另行取得检验结果和授权。

项目部署工作流：OSS 制品到系统服务

本例按 Linux VM 上的应用进程部署设计。检验阶段确定本次计划与输入，执行阶段按审核后的规程和申请操作。每个步骤都先取得自己的有效检验产物。每次部署固定制品、配置和步骤版本。人工输入、步骤证据和当前状态持久保存；Agent 对话中断不会丢失部署进度。

每个执行步骤都先经过Harness 门禁。展开的文件清单、INI、参数、密钥版本或目标改变时，重新核验受影响的申请、DRY-RUN 和审批。预检只生成计划或验证隔离副本；下载、写文件、设置权限、连通检查、试启动和服务注册均按各自申请执行，不能因为属于同一工作流就跳过门禁。

步骤执行者与产物通过条件与失败处理
固定部署输入用户指定项目、环境和目标。Agent 整理部署清单，管理员审核脚本及适配器版本。明确对象存储位置、制品摘要、目录规则、运行身份、配置、启动定义和健康判据。必需信息缺失时暂停。
从 OSS 下载执行面通过已审核的对象存储适配器下载到版本化暂存目录，保存对象身份、版本、摘要和来源。校验可信清单中的内容摘要；不接受未固定的“最新文件”。下载不完整或摘要不符时禁止继续。
文件与 INI 归类项目布局处理器按文件名、文件类型和已审核的 INI 字段生成目录映射。执行面按映射准备候选版本。映射只使用批准根目录内的路径。路径逃逸、未知文件或冲突须明确报错。INI 作为数据解析，不能注入任意命令或外部路径。
设置运行身份与权限执行面核验或创建服务用户、所属组，并设置目录和文件的读写及执行权限，保存差异记录。代码和配置默认不允许服务用户修改；日志与业务数据使用指定可写目录。用户、目录或权限不符合清单时停止。
人工填写密钥与连通配置人工通过受控入口填写启动密钥，写入执行面的凭证库。非敏感连接参数进入版本化配置。工作流只保存密钥引用与版本；已有密钥可经密钥剪贴板由受控工具内部取用，再写入已授权工具或目标位置。缺少必需密钥时进入“等待人工输入”。密钥明文不进入任何 Agent 对话、OSS 制品或审计输出；执行面在检验与授权通过后传递或注入目标。Agent 不能用通用文件读取工具打开源密钥或目标副本。
基本检查执行面按固定检查版本核验依赖、CPU 架构、配置、目录权限、空间、端口和允许的外部连接，保存结果。全部必需检查通过才允许试启动。命令先 DRY-RUN；涉及数据库查询或迁移时，SQL 先按目标类型和版本分析。
受控试启动执行面使用候选版本、固定运行用户、工作目录、配置和密钥引用启动应用。收集脱敏 stdout/stderr、退出状态、就绪结果和观察期证据。试启动是实际执行。日志判据、就绪检查和观察期须一起通过；不能只凭一条“启动成功”输出。启动钩子中的数据库查询、迁移及 SQL 脚本须纳入 SQL 分析；实际内容无法确定时阻断。失败时停止晋级，按已批准的停止与补偿步骤处理。
验收并注册系统服务管理员确认试启动结果。执行面先确认试运行进程已停止，再通过服务适配器注册、启用并启动同一候选版本。固定启动入口、用户、工作目录、制品及配置版本。停止、替换和服务配置变更须具备对应审批；不能让试运行和正式服务争用同一实例或端口。
正式服务验收执行面核验服务状态和应用健康，把主机、版本、配置、服务身份及依赖证据写入事实地图，并接入独立监控旁路。正式运行通过后才标记部署完成。失败时记录实际状态并报警，禁止把“服务已注册”记为部署成功。

系统服务沿用固定启动定义和崩溃重启策略。重启策略须经独立 JEV 审核及人工批准，明确目标、启动定义、适用条件、次数范围和有效期。每次自动启动由受控启动入口核验目标、内容摘要、配置和密钥版本，以及仍有效的 JEV 裁决、DRY-RUN、所需 SQL 分析和人工授权，并记录审计。可以复用仍有效且覆盖相同操作的产物；超出覆盖范围、条件变化、产物失效或无法完成核验时禁止启动，并重新进入 Harness。启动、停止、重载及清理钩子中的命令和 SQL 也须纳入门禁。原生服务管理器不能落实这些约束时，相应自动启动能力保持不可用。

本例的宿主应用由 systemd 管理，可按目标版本采用 Restart=on-failure、重启间隔及频率上限。达到上限后停止重试，由旁路报警。开机自启另行在服务策略中声明。已有 Supervisor 环境可选择对应服务适配器；Docker 应用使用容器策略。每个实例只有一个重启管理者。平台底座的 Supervisor 职责见Docker 部署底座。Agent 不参与正常的服务保活循环。

部署任务保存 workflow_id、step_id、目标与版本、状态、证据引用及补偿计划。失败后先核验目标现状，再决定续跑或执行已批准的补偿。不得因 Agent 或执行器重启而重复创建用户、覆盖文件或启动进程；恢复申请须重新核验执行条件。候选制品、旧配置和服务状态分别保存，不能把本地文件回退视为数据库或远端状态回滚。

项目部署规程包与派生接口

部署模板是规程包的参数和步骤描述。模板最少包含：项目与环境、目标资源 ID、对象存储位置及固定版本或可信摘要、布局规则版本、运行用户和权限、配置及密钥引用、网络依赖、启动定义、健康判据、服务策略、恢复步骤和所需审批。制品目录与目标安装目录由执行面管理；Agent 的只读工作区规则继续适用。

项目可派生制品获取与校验、文件布局、配置解析、健康检查和服务注册适配器。派生只重写对应业务方法，框架继续固定执行门禁、状态机和审计。每个项目派生文件独立维护，管理员审核并固定版本后启用；生成模板不自动注册工具或 skill。以下均为设计约定，当前不创建部署源码或真实服务。

技术依据：OSS GetObject 与对象版本、systemd 服务与重启策略、Docker 容器重启策略。具体服务能力按目标运行时版本核验。

项目 Agent 生成与启用

项目 Agent 是绑定项目的逻辑身份，关联项目知识来源、审核后的部署与检查任务、环境权限、对话和执行记录。它是业务范围，不是部署单位；不要求一个项目对应一台 VM 或一个核心 Docker 实例。

资料项最少内容

环境与资产环境、服务商、账号、区域、资源、数据库类型与版本、凭证引用。
监控要求监控对象、指标、阈值、周期、时区和通知方式。
成员与审核项目成员、环境权限及部署、检查和变更的审核权限。
  1. 收集资料并整理。Agent 可按文档和流程描述拆解内容并追问缺项。未知项明确标记，不推测成事实。
  2. 登记环境并核验事实。绑定服务商、账号、区域和资源，核验目标环境。所有实际操作仍由 Harness 执行。
  3. 整理部署任务。在检验阶段把手工部署流程整理成候选规程、版本化脚本草稿和任务参数，持续补问未确定事项。不得自动注册工具或 skill。
  4. 整理监控任务。生成固定检查任务草稿、CRONTAB 时间规则和报警规则，等待审核。
  5. 执行受控预检和必要试运行。管理员先审核并固定参与试运行的脚本和检查版本。仅在已授权的隔离或测试环境中经 Harness 执行。写操作先经人审；没有实际且已授权的目标时不得试跑。
  6. 管理员审核并启用。审核知识来源、脚本、检查任务和权限，固定版本后启用项目 Agent。部署规程按两阶段规则另行核验并登记；Agent 启用不等于部署规程定版，也不跳过每次任务的独立子 Agent 复核、DRY-RUN、SQL 语法分析及既有审批。

产物包括项目档案、环境映射、知识索引、审核后的部署脚本、监控检查与时间规则、权限策略和验收记录。缺少必需的执行证据时仍可保存资料，但相应能力保持不可执行。

02总体架构

核心容器承载按模块组织的 Go 业务服务，包括项目、任务、审批和事实地图。业务模块共享一个控制服务进程，通过明确接口协作。Agent Worker 采用 Go 开发，使用独立容器，嵌入独立 GoAgent SDK，并通过本项目定义的版本化队列协议与核心交互。资产访问和宿主 Docker 控制通过受控接口完成。执行面在核心容器外核验授权，不能仅相信容器内提交的“已通过”标记。

核心接口不等待模型调用完成。模型请求使用超时、有限重试和熔断。Worker 故障只使相关任务失败或等待恢复，核心面板、任务记录和配置查询仍可使用。Worker 独立设置资源限额和重启策略，不能因积压耗尽核心资源。

组件职责权限边界
接入与业务面板项目对话、部署、测试库操作、CRONTAB、IM、告警回调、审批和事实地图查询。身份、项目和环境授权先于业务请求。告警入口须鉴权、去重并映射到受控任务。

审计服务保存命令、SQL、API 请求、预检产物、子 Agent 裁决、人工审批、执行输出与部署操作。位于核心容器外。Agent 不能修改审计记录。容器删除与镜像回退不能删除审计链。

03Docker 部署底座

每个核心运行实例由一个 Docker 容器承载，关联独立的 Agent Worker 容器。简易 Docker 管理平台提供独立管理员入口。平台控制服务维护目标 VM 和部署模板，节点执行器调用目标 VM 的本机 Docker Engine。

平台分别启动、停止、重启、更新和回退核心与 Worker 容器。管理员分别查看核心健康、Worker 状态和模型可用性。Supervisor 指宿主侧的 supervisord，负责平台进程托管。

运行主体管理对象职责
宿主系统Docker daemon、Supervisor启动和维护基础服务。Docker daemon 不作为平台子进程交给 Supervisor 托管。
Supervisor平台控制服务、节点执行器托管宿主子进程，记录进程状态，并按配置启动或恢复进程。
Docker 管理平台VM 清单、环境模板、部署申请核验目标、审核配置、分发部署包，分别管理核心和 Worker 容器、日志与健康。
Docker Engine核心与 Worker 容器分别创建、启动、停止和删除容器。按各自审核后的重启策略维护状态。

Supervisor 托管平台进程。核心容器的重启由 Docker Engine 负责，同一容器只有一个重启责任方。技术依据：Supervisor 进程管理、Docker 重启策略。

平台管理入口运行在核心容器外。核心容器停机时，管理员仍可检查部署、查看日志和恢复核心。Docker 管理权限只授予节点执行器；远程管理请求通过已认证的节点通道。

Docker socket 和宿主控制凭证仅在底座节点执行器的权限域内使用。核心容器通过受控接口提交申请。工作区文件和临时产物的访问也须经过工具边界，不能借业务工具取得宿主管理权限。

不同 VM 可运行独立核心实例。每个实例绑定任务范围与数据。Worker 通过任务租约处理该实例的模型任务，租约过期后的输出不能直接触发执行。模型失败使相关任务降级，核心仍返回任务状态。容器为 running 时仍须核验应用健康。

工具隔离与工作区

工具运行时与核心部署容器分别管理。执行面通过统一接口创建或恢复任务环境、导出工作区、执行工具并回收环境。管理员为工具绑定已审核的沙盒策略，策略明确运行时、镜像、资源、工作区和网络。

策略能力运行时接口约束
MicroVM 快照路径该路径启用时，从内核与工具已就绪的干净基线恢复任务环境，以减少重复启动。基线不含任务数据或凭证。每个任务使用独立临时空间。恢复后安全重置实例标识、随机状态、时钟及连接。快照、磁盘和运行版本分别核验；任务结束后回收实例。
Docker 只读工作区路径该路径启用时，只导出白名单目录，并以 readonly/ro 挂载。敏感文件须过滤或不导出。临时产物使用独立可写目录。所有文件工具与 terminal 使用同一工作区边界。禁用递归子挂载，或核验所有子挂载也为只读。
共同边界工具环境不持有 Docker socket 或宿主管理权限。环境恢复和文件访问遵守同一白名单、审计及审批规则。凭证只在授权后注入受控工具后端，Agent 不能读取源或注入副本。密钥文件不导出为只读工作区。沙盒快照只恢复本地状态，不能回滚远端操作。审计保存在沙盒外。

05Harness 与受控执行

Harness 是执行框架，负责强制门禁和任务状态。约束由核心容器外的框架与执行器落实。Agent 提示词不能代替执行门禁。项目操作、工具调用、脚本、SQL、云 API、底座部署及定时触发使用同一申请路径。

本系统的人工终端和应急通道也必须落实命令 DRY-RUN 与 SQL 语法分析。交互式输入不能绕过预检。预检服务不可用时禁止执行，审批不能豁免这些门禁。

JEV 是独立审核子 Agent，使用与主对话 Agent 分开的审计模型配置。所有 Agent 的执行申请都必须由审核子 Agent 复核，包括子 Agent 继续提出的操作。单纯对计划进行审核不产生执行申请；审核子 Agent 要调用工具时，仍须提交受控申请，由另一审核实例复核。

Bash 与 SQL：检验 → 执行

每次命令或 SQL 都先形成固定执行规格，再完成所需检验。已有模板和适配器用于生成与检验本次内容；方法登记状态不能代替本次检验。框架分别保存本次检验结论，以及等待审批、执行中、成功或失败等任务状态。

操作检验阶段执行阶段
Bash / 脚本 / 命令完整展开命令和参数，核验目标、路径、身份、影响、预期结果及补偿方案，完成有效 DRY-RUN。JEV 复核产物，取得所需人审。执行面核验当前目标、事实和与本次申请匹配的有效产物，再执行固定内容。Bash 调用 SQL 时还须 SQL 检验通过。
SQL按数据库产品、方言和版本分析完整语句及动态展开结果，核验对象、参数类型、权限、影响、预期结果和事务或补偿方案。JEV 复核并取得适用人审。SQL 执行器核验本次分析结果及全部授权，再执行相同语句和参数。查询、数据变更及表结构操作都先检验。

可复用方法经 JEV 复核与管理员审核后固定版本并登记白名单。一次性命令或 SQL 也可形成绑定固定内容的单次申请，先检验通过后执行；这不会自动注册新工具或 skill。本次记录保存申请摘要、inspection_id、方法版本、目标作用域、检验产物和执行结果。

检验未通过时阻断本次执行，并补充证据或修订申请后重新检验。需要修改方法、预检能力、方言支持或适用范围时，建立新版本草稿重新审核。任何内容、参数或条件变化都核验受影响的检验产物，不能沿用不匹配的旧证据。

  1. 接入层识别来源、项目和身份。人工、CRONTAB、告警或自愈任务进入受控会话，并绑定项目和目标环境。
  2. Agent 提交固定的执行申请。申请包含项目、目标 ID、环境、脚本或 SQL 内容、非敏感参数、密钥绑定引用、云产品操作、工作流上下文、事实与配置版本。框架计算申请摘要，后续产物均绑定该摘要。
  3. 控制面核验事实、权限与白名单。验证目标、工具权限、项目成员权限、环境授权和工作流约束。关键事实未知、过期或冲突时暂停相关变更。
  4. DCG 检查确定性规则。DCG 是命令与操作规则检查，命中阻断规则即拒绝。模型裁决或 DRY-RUN 不能覆盖阻断结果。
  5. 审核子 Agent 复核计划。独立审核申请、预检方法和影响范围。初审通过只允许指定预检；不能授权正式执行。
  6. Harness 完成所需预检。所有 Bash、脚本及其他命令必须完成 DRY-RUN。所有 SQL 必须完成语法分析。经 Bash 调用 SQL 时，两项都必须通过。
  7. 审核子 Agent 复核预检产物。JEV 对同一申请及其产物输出通过、拒绝或需补证的裁决。缺少有效通过裁决时，正式执行保持阻断。
  8. 危险操作交给人工终审。删除、重启和配置变更等危险操作按环境授权规则审批。测试环境支持所需的数据和表结构操作，仍须满足对应审批规则。
  9. 执行器重新核验全部条件。核验目标、申请摘要、事实、配置、预检及审批。内容、参数、身份、方言版本或影响范围变化时，相关结果失效，重新申请。
  10. 执行面注入凭证并执行。只执行被核验的固定内容。命令经跳板访问资产；云产品通过已审核适配器调用对应 API。SQL 执行器再次核验分析结果。受控工具按剪贴板编号内部取用，并按批准目标写入，明文不进入 Agent 申请。返回结果按字段允许清单过滤并脱敏后再进入模型。
  11. 控制面保存结果并核验实际状态。结果绑定项目与任务。审计服务保存申请、预检、规则结果、子 Agent 裁决、审批、执行输出和事实引用。

强制产物与失效条件

门禁必须保存的产物阻断条件
子 Agent 审核审核实例、申请摘要、证据引用、裁决、理由和有效期。自审、审核缺失、拒绝、需补证、内容不匹配或裁决过期。
Bash / 命令 DRY-RUN固定版本的预演适配器、展开后的命令和参数、目标作用域、预期变更、覆盖范围、结果和时间。无受支持的预演方式、未通过、动态内容未覆盖或产物失效。只读命令也不得跳过。
SQL 语法分析原始 SQL 摘要、完整语句列表、参数类型、数据库类型与版本、解析结果、对象引用和语句类别。未分析、解析失败、方言不支持、部分语句遗漏或目标版本不匹配。查询和表结构操作均适用。

DRY-RUN 必须由已审核且版本固定的预演适配器完成，并保证不修改目标业务状态。适配器可生成变更计划，或在隔离副本中验证；必须声明覆盖范围。仅输出一行命令、让模型模拟结果或只做 bash -n 语法检查，不能形成有效的 DRY-RUN 产物。没有可验证的预演路径时，Harness 禁止执行。

预检服务只开放已审核的分析与预演接口，不开放任意 shell。预检组件生成自己的受控记录，不递归生成同一操作的 DRY-RUN。初审只授予该次预检权限，不能注入正式执行的写入凭证。

SQL 分析按目标类型、产品方言和版本解析完整输入。多语句脚本须逐条覆盖。运行中拼接的 SQL、存储过程及函数内语句必须纳入相应分析；无法确定实际内容或作用范围时阻断。语法通过后还须检查对象、权限和影响范围，再完成子 Agent 审核与适用审批。

SQL 语法分析使用支持目标方言的分析组件。PREPARE 或 EXPLAIN 只能按数据库适配器声明的语句范围补充校验。EXPLAIN ANALYZE 会实际执行语句，不能充当无副作用的语法分析。

技术依据：Bash 语法检查语义、PostgreSQL PREPARE 的适用语句、PostgreSQL EXPLAIN 的执行行为。

云 API 操作使用适配器声明的计划和校验能力。经 CLI 或 Bash 调用云 API 时，仍须命令 DRY-RUN；其中包含 SQL 时，还须 SQL 分析。切换调用形式不能绕过所需门禁。

底座部署操作遵守同一组审批与审计规则。平台在核心不可用时仍保留管理员恢复入口，校验所需的服务和审计通道位于核心容器外。

Agent 全局变量区与密钥剪贴板

密钥剪贴板属于 Agent 的工具与全局变量体系。它通过受控工具管理敏感内容，并返回编号和非敏感备注。全局变量区以编号和备注引用条目，不保存 Agent 可读的密钥明文。本文其他流程中的密钥引用在 Agent 工具层以剪贴板编号表示。

用户和所有 Agent 都不能显示、读取或导出保存的密钥。

主 Agent、子 Agent 和审核 Agent 只使用编号、备注和操作状态。工具可在受控后端内部查询对应值，并按已检验申请拷贝或写入授权目标。明文不进入 Agent 对话、模型可见参数、工作区、日志返回或审计输出。

核心能力已确定的行为
增通过受控工具存入敏感内容，生成编号和非敏感备注。新增结果不回显内容。
删通过受控工具移除条目。删除后不能继续通过旧引用使用内容。
改通过受控工具修改内容或备注。修改不向用户或 Agent 显示原值或新值。
工具查受控工具内部查询并取用对应值，可写入已授权工具或目标位置。返回给 Agent 和用户的只有编号、备注及操作状态。

所有操作遵守先检验，再执行，并满足既有权限、独立审核、所需预检和审计要求。经 Bash 或 SQL 操作时，相应强制门禁仍适用。全局变量区的统一引用范围不能代替具体操作授权。

本阶段只确定核心能力与密钥不可读边界。密钥匹配、编号规则、存储、接口及生命周期细节留待后续设计。

06运维事实地图

地图的底层是结构化事实库。系统、部署和网络视图共用这些事实。控制面据此选择目标、核验前置条件和分析已知影响范围。

对象使用稳定 ID。每个 ID 绑定项目、云服务商、账号或资源管理域、区域及环境作用域。名称和 IP 只作为属性，不能单独作为唯一身份。

对象记录内容主要关系
项目与环境项目 ID、成员、环境定义、资料、应用、数据库、脚本版本和 CRONTAB 任务的归属。业务对象 → 归属 → 项目；任务 → 指向 → 环境
宿主云主机、VM 或物理机的稳定 ID、环境、账号、区域、接口和负责人。运行实例 → 运行于 → 宿主
应用与实例逻辑应用 app_id、进程/容器/Pod 实例 ID、版本、端口和健康状态。实例 → 属于 → 应用
配置配置来源、期望版本、实际加载版本、脱敏差异和适用实例。实例 → 加载 → 配置版本
API 与入口所属应用、域名、路径、协议、端口及网关映射。应用 A → 调用 → 应用 B 的 API
网络虚拟私有网络、子网、路由、接口、安全组、防火墙、地址转换与域名解析。网关 → 路由到 → 实例
数据依赖数据库、缓存、队列及外部 API。数据库记录供应商产品、基础类型、派生类型、版本、库和 schema。应用 → 读写/发布/订阅 → 依赖
云产品与能力供应商、产品、API 版本、账号、区域、稳定资源 ID、适配器版本与已核验能力。抽象资源 → 映射到 → 供应商产品资源
平台自身VM、核心实例、镜像摘要、配置映射与四类独立运行状态。核心实例 → 部署于 → 登记 VM

每个对象、关系和关键属性记录来源、采集时间、有效期、证据引用、核验状态和事实版本。模型可以提出候选关系，可信采集或受控人工核验负责确认。

三类证据分别呈现

  • 配置声明：说明配置中声明了依赖。配置文件存在某版本，不能证明实例已经加载该版本。
  • 网络策略：说明源、目的、协议和端口的允许或拒绝规则。策略允许不能证明端到端可达或曾发生调用。
  • 实际观测：API 日志或调用链支持具体 API 关系。流日志只记录其观测范围内的流量和处理结果。采样和丢失须显示在覆盖范围中。

技术依据：AWS 安全组规则、AWS 流日志字段、OpenTelemetry 采样。

地图支持按项目、环境、供应商、宿主和应用筛选。查询遵守项目和环境访问范围。选择一个 API 时，可沿有证据的调用关系查询调用方和下游。选择一个实例时，可追溯宿主、配置及网络策略。关系详情显示证据、时间窗口、覆盖范围和事实版本。

事实库保留变更历史。变更申请引用目标 ID、事实版本和配置版本。执行前的重新核验结果也进入审计记录。

采集由执行面通过白名单中的只读接口完成。敏感配置在入库前脱敏。事实库保存密钥引用。来源冲突、采集失效和过期值必须可见，缺少观测不能推导出“没有依赖”。

07云服务商 API 层

云资源操作面向项目登记的 VM、负载均衡、数据库和对象存储等资产。调用按项目、环境、账号、区域和稳定资源 ID 定位。凭证只在执行面持有；云 API 请求进入白名单、独立审核子 Agent 复核、变更计划、审批、影响核验和审计流程。

API 分三层组织。能力因服务商或产品而异；未提供或未验证的能力必须明确标为不可用。统一对象模型不表示各服务商 API、异步任务、状态和错误完全相同。

层职责边界
抽象层定义服务器/VM、Docker/容器运行、负载均衡、数据库和对象存储等统一对象与能力接口。只统一稳定的共同概念；保留产品差异，不虚构未具备的能力。
对接层按供应商和产品调用各自 API，并归一可比的状态、错误和任务标识。分别对接 Azure、阿里云和腾讯云。具体产品只实现其实际支持的 API；不支持的能力明确不可用。
派生层适配具体数据库产品及版本，描述方言、能力和 SQL 语法分析规则。每个派生数据库类型独立维护，分析结果须匹配目标数据库类型和版本。

Docker 抽象优先通过 VM 上的节点执行器受控访问本地 Docker Engine。供应商托管的容器产品使用独立产品适配器；云 API 不是 Docker socket。平台自身 Docker 底座管理核心与 Worker 的部署；项目容器属于项目资产操作，由执行面按项目权限管理。

云数据库管理 API 负责实例、规格、网络和备份等产品管理。库表和数据操作通过数据库连接与 SQL 执行器完成，绑定基础类型、派生类型和引擎版本，并执行 SQL 分析。厂商支持 SQL API 时，该入口仍必须提供同一分析产物。

对象存储抽象为部署制品提供定位、版本核验和下载能力，本例通过阿里云 OSS 产品适配器实现。对象位置绑定账号、区域、bucket、object key，以及可用的对象版本和可信内容摘要。版本能力未启用时，必须用可信摘要核验下载内容。读取凭证和签名链接只在受控执行面使用，不能把含凭证的下载地址交给 Agent 或写入审计输出。

适配器记录 API 版本、能力清单、计划或原生预检支持、幂等方式、异步任务和错误语义。执行结果保留厂商请求 ID 与资源 ID；只有任务完成并核验实际状态后才记为成功。结果未知时先查询和核验，不能盲目重发变更请求。

预检调用适配器的计划或分析入口，正式执行调用执行入口。两类入口使用不同权限。计划产物不能通过调用同一适配器而升级为执行授权。

不同 API 的预检成功含义由各适配器解释。例如，阿里云 ECS 的指定预检成功以 DryRunOperation 错误码返回，腾讯云 CVM 的指定预检成功返回请求 ID。统一层保存归一结果及原始依据，不凭 HTTP 状态猜测是否通过。

对接依据：Azure VM API、阿里云 ECS CreateInstance、腾讯云 CVM RunInstances。

同一逻辑实例跨 VM 迁移

  1. 管理员发起并批准迁移。固定目标 VM、镜像、配置与状态恢复映射，核验环境和存储兼容性。
  2. 控制面暂停该实例的新任务和定时触发。处理在途任务及 Worker 租约，确认远端操作与审计状态。独立监控旁路继续运行。
  3. 平台停止旧实例和相关 Worker。撤销旧任务租约，并关闭自动重建路径。不能确认旧实例和任务执行者停止时，暂停迁移。
  4. 平台恢复状态并部署新实例。核验会话、任务、配置和健康。相同逻辑实例只保留一个活动执行者。
  5. 平台切换入口，控制面恢复任务。核验执行上下文并保存迁移审计。镜像回退需要兼容性校验，不能当作数据库或远端操作回滚。

09监控旁路与模块

独立采集与报警链路

监控、采集和报警构成独立旁路。固定采集器把指标、日志和事实证据写入各自的持久存储。固定规则服务计算状态。报警服务持久化事件并通知外部接收方，再异步提交受控诊断任务。通知失败由旁路重试，不等待 Agent 响应。采集、规则计算和通知不依赖 LLM、Agent Worker 或核心容器存活。旁路使用独立生命周期、持久存储和资源限额。监控节点默认与核心及 Agent 所在 VM 隔离。Agent 停止时，旁路继续运行，事件保留供恢复后查询。

优先集成现有外部监控和云监控。没有可用指标系统时，指标旁路默认采用 Prometheus、Alertmanager 和 Grafana。日志和调用链按需接入现有存储，不预设必须部署某套日志或追踪产品。CRONTAB 只触发业务巡检和周期事实采集，由独立调度执行服务调用固定检查版本；保留成功、失败、缺测和最近成功时间。纯指标 HTTP 拉取不触发模型推理。

固定采集、规则和通知遵守架构内核的输入、配置、权限、输出及失败校验。使用密钥时由受控后端按批准引用注入。含敏感信息的原始证据隔离保存，Agent 查询与派生处理器输出仅提供允许的脱敏字段或证据引用，不能暴露密钥。

项目 Agent 经受控只读接口查询监控。Agent 可提出采集器安装或升级、采集/报警配置变更、静默和修复申请；管理员审核并固定配置版本，Harness 执行变更。Agent 不直接改配置、不静默报警、不取得宿主权限。固定且已审核的采集组件按配置持续采集。Exporter 若不能把其数据库 SQL 纳入目标类型与版本分析门禁，或脚本不能通过 DRY-RUN，就不得启用。监控不能为脚本或 SQL 开免检路径。

事实采集由 provider、Docker、API 和配置适配器写入事实库，并保存来源、证据和采集时间。指标只说明其测量范围；例如 CPU 数值不能证明应用间发生了 API 调用。CRONTAB 检查结果也保存缺测、失败和最近成功时间。Agent Worker 故障不阻断固定检查。JEV 或预检组件不可用时，相关命令和 SQL 任务阻断并报警；纯指标旁路继续运行。人工、告警和闭环发起仍共用受控执行路径，危险操作继续人工终审。

Prometheus 负责采集与规则计算，Alertmanager 负责报警分组、去重、路由和接收方通知。CRONTAB 只决定检查何时触发；检查内容、版本、目标环境和执行授权由受控配置确定。命令与 SQL 门禁见受控执行路径。

格式与派生处理器（PATCH 扩展）

PATCH 表示对业务扩展点提供专用实现。Go 使用接口和组合实现这种派生能力。基础格式为 StringParser、XmlParser、JsonParser 和 BinaryParser。派生处理器可实现专用 match、parse、normalize，并增加业务 validate。最终结构校验由框架固定执行，不能覆盖。

固定调度器调用已选处理器的接口，处理器组合基础格式的解码和校验函数。Go 的嵌入只提供方法提升，不提供类继承的虚方法分派。基础对象内部的方法调用不会因外层定义同名方法而自动转向外层。扩展必须通过选定的接口实例调用，避免 PATCH 仅声明却未生效。参见 Go 接口与嵌入说明。

格式派生规则
字符串可按业务子类型派生，如 kv_line、multiline、app_status。名称仅表示处理角色，不代表已有具体应用。
XML / JSON分别按来源与已登记 schema 派生，保留格式、来源和 schema 版本。
二进制 / ProtobufProtobufParser 从 BinaryParser 派生，使用已登记的 descriptor/schema、消息类型和版本解码，再规范化为统一结果。二进制本身不足以确定业务字段含义。参见Protobuf 编码说明。

匹配优先使用明确的来源、格式和子类型，再使用管理员审核的规则及优先级。同级最高匹配冲突时标为冲突。未命中或二进制 schema 缺失时，保留原始证据并标为未知，不能自动判健康。解析失败须单独记录。禁止把乱码自动回退为字符串处理。框架限制输入大小、嵌套深度和处理时间；XML 禁用外部实体。重放使用原始证据和当时的处理器、schema、配置版本核验结果，不重复发送历史告警或执行修复。

处理器只在受权限和资源限额约束的独立模块 Worker 中运行，不对核心进程做运行时 monkey patch。它不能替换调度、门禁、凭证获取、审计或告警路由。模块清单固定 module_id、source、format、subtype、处理器及版本、schema、匹配优先级、依赖、权限、运行限额和内容 hash；管理员审核、验收后固定版本启用。

11Go 内核、GoAgent SDK 与阶段开发

本系统采用 Go 开发。Agent 能力封装为可嵌入的独立 Go SDK。

平台按业务模块开发。权限边界按独立进程部署。每个阶段交付一个可验收的范围，并复测此前已交付的关键路径。需要缩短迭代时缩小范围，已知安全、一致性、兼容和恢复缺陷不能留到后续版本。

Go 负责固定规则、状态转换、接口契约、资源限制和受控执行。模型负责理解、问答、计划与审核建议。模型输出仍是待检验输入；Go 并不能让模型推理、远端网络或云 API 自动获得确定性。

生态选型与准入条件

工具链基线按 2026-10-05 的 Go 官方下载页核对：平台固定 Go 1.27.1。GoAgent SDK 的最低支持版本设为 Go 1.26，并在 Go 1.26.8 与 1.27.1 上复测。依赖版本、构建镜像和目标平台写入发布清单。安全更新经过复测后更新清单，不使用随时间变化的 latest 作为构建输入。

职责实现基线使用边界与检验
服务与生命周期优先采用标准库 net/http、context 和 slog。初始服务契约采用版本化 HTTP/JSON。请求有 deadline、取消、输入限制和有界并发。核心 API 异步提交 Agent 任务。日志字段先脱敏。仅在确有契约与性能需要时增加 gRPC，不同时维护两套等价接口。
业务状态与 SQLPostgreSQL 作为核心持久状态基线。驱动用 pgx/v5；固定 SQL 可用 sqlc 生成类型接口。驱动与生成器只留在存储适配层。sqlc 的 Go 支持覆盖 PostgreSQL、MySQL，但生成代码不能替代运行前 SQL 分析。平台 SQL、迁移 SQL 和巡检 SQL 均进入同一产品与版本分析路径。事务与辅助语句也不能形成旁路。
数据库迁移首版使用审核后的版本化 SQL 文件，经专用迁移执行器运行。goose 仅作为通过兼容检验后的迁移工具候选。初始化、元数据查询、迁移和回退语句都先分析。不能在核心启动时自动运行未检验迁移，也不能用 Go 回调隐藏动态 SQL。运行身份与迁移身份分开。
PostgreSQL 分析pg_query_go 使用 PostgreSQL 的解析器源码，是目标方言分析候选。它依赖 CGO，即 Go 与 C 的构建边界。P0 验证目标数据库主版本、解析器版本、amd64/arm64 构建和镜像运行。语法树不能证明权限、执行影响或数据安全；这些另由固定规则和审核检验。
MySQL 与派生产品分析TiDB parser 是纯 Go 的 MySQL 方言候选。MySQL 兼容不等于每个 MySQL、TiDB 或云派生产品完全等价。按产品、确切版本、SQL mode 和语句特性建立覆盖矩阵。未支持、多语句漏析、动态 SQL 未展开或分析不完整均阻断。每个派生类型使用独立 Go 文件。
项目流程首版在平台应用层实现限域的持久化项目状态机，覆盖已定义的部署步骤、审批、待输入、暂停和恢复。通过平台的 WorkflowPort 隔离编排实现。先保存状态、执行意图和稳定幂等键，再发起操作。用租约和隔离令牌阻止旧执行者继续操作。结果不明时先查询目标实际状态，不盲目重放。首版不开放任意流程图编排；状态机与失败路径须在 P3 全部验收。
长流程扩展候选Temporal 提供持久工作流与独立 Worker，适合长期等待和故障恢复。其 Server 还使用独立持久层。目前核实的官方配置能力不能证明支持本系统逐条 Server SQL 的前置分析门禁。P0 必须验证运行、初始化和升级 SQL 均受控；未通过就不启用。SDK 不依赖 Temporal；不为中间件豁免 SQL 检验。
CRONTABrobfig/cron/v3 用于表达式与时区解析。持久调度状态由独立调度执行服务保存。内存计时器不能作为任务唯一来源。每次触发绑定项目、规程版本和唯一周期键。明确时区、夏令时、错过时刻、重叠与补跑策略。恢复不重复触发已接受的周期；Bash/SQL 仍逐次经过门禁。
Docker 与多云对接Docker 使用官方 Moby Go client，模块路径为 github.com/moby/moby/client。云层使用 Azure、阿里云、腾讯云的官方 Go SDK。每个产品适配器固定依赖与 API 版本。能力矩阵先声明预检、幂等、状态查询和失败恢复支持。厂商返回任务 ID 不等于执行成功；厂商 SDK 也不提供本系统的 Harness 门禁。
Agent 框架Eino 和 Google ADK Go 作为模型与编排适配候选。本项目 SDK 的公共契约自行定义。P0 检验所有工具回调、并行调用、子 Agent、流式和恢复路径。任何框架内置执行器都不能直连 shell、SQL 或云资源。候选不满足门禁时不采用；不同时引入两套执行框架，也不把候选框架类型暴露为 SDK 公共 API。
观测与旁路指标用 Prometheus Go client；日志用 slog；调用链按需采用 OpenTelemetry Go。平台只暴露受控指标与追踪。旁路独立保存、计算和通知。SDK 注入观测接口，不创建全局 exporter。首版不依赖仍需另行检验的日志信号管线；敏感参数不进入标签、日志或追踪。
测试与依赖检查使用 Go 的 race detector、fuzzing、govulncheck，并用 Testcontainers Go 检验真实数据库行为。race 只能发现已运行路径上的竞态。fuzz 检验解析与输入边界。真实服务检验 SQL 方言、事务、租约和恢复。工具结果、依赖许可与维护状态进入发布记录；缺少关键测试时不能宣称该能力可用。

上表区分实现基线与需要证明兼容的候选。候选均未表示已通过 PoC（小范围原型验证）。P0 记录证据与结论；未通过的能力保持禁用，不先接入再补门禁。

GoAgent SDK：模型、上下文、工具与运行管理

GoAgent 是本项目独立的 Agent SDK，本文统一称为 GoAgent SDK。它具有自己的 go.mod、版本和公共导入 API。其他 Go 系统在自身进程中嵌入它。本平台的独立 Agent Worker 同样嵌入这个 SDK。平台 HTTP 客户端与 GoAgent SDK 分别承担远端访问和本地 Agent 运行职责。

边界确定的职责
公共 API模型访问与请求管理、会话与上下文、计划、工具登记与申请、公开事件枚举、Hook 扩展和检查点。采用本项目定义的 Session、ModelRequest、ModelEvent、ContextSnapshot、Plan、ToolSpec、ToolRequest、ToolResult、EventType、Event 与 Hook 契约等公共类型。调用者传入 context，掌握取消和生命周期。接口不暴露平台内部实体、数据库行、厂商或 Agent 框架类型。
SDK 内部管理模型协议、请求生命周期、上下文维护与压缩、工具目录与调用、事件流、检查点和子 Agent 会话。限制轮数、时间、并发、队列和输出大小。子 Agent 与主 Agent 共用受控工具路径。SDK 不自行启动服务、迁移数据库、注册系统任务或创建包级全局运行状态。
宿主注入端口ModelPort 定义统一模型调用。SDK 的 ManagedModelClient 实现协议与请求管理，并使用宿主注入的 AuthenticatedTransportPort 发送请求；宿主也可提供已验收的兼容 ModelPort。SessionStore 保存会话与检查点；GatedToolRequestPort 提交全部受控工具申请；Observer 接收脱敏事件；可信宿主通过固定版本 HookRegistry 登记扩展。模型凭证只在受控传输后端注入，SDK 不接收明文密钥或敏感认证头。
平台扩展项目知识、运维提示词、工具目录、规程、Harness 协议与工作流适配由平台提供。SDK 不导入平台的 internal 包，也不绑定 PostgreSQL、Docker、多云、Temporal、CGO 或某个运维项目。模型协议与厂商 PATCH 是 SDK 的可复用适配能力。项目资源操作仍由平台工具提供。可选框架实现留在适配模块，公共契约保持稳定。
执行安全SDK 只生成工具执行申请。宿主 Harness 完成独立子 Agent 审核、实际预检、产物复核和适用人审。宿主执行器在执行时重新检验固定内容、目标、scope、版本与有效期。缺少必要宿主能力时只开放对话与计划，工具执行关闭。approved=true 等 SDK 标记不能形成执行授权。
密钥与结果SDK 只处理剪贴板编号、非敏感备注和受控状态。模型输入、事件、工具结果、错误和会话持久化均先过滤敏感内容。工具查由宿主受控后端内部完成，明文不返回任何用户或 Agent。剪贴板接口、匹配和存储细节仍后续设计。

接入验收第二个 Go 宿主必须不依赖平台数据库与平台服务即可运行对话和计划。执行能力只在接入等价门禁后开放。复测公共 API、事件、取消、并发、子 Agent、旧调用方编译与越权负例。SDK 不能约束宿主另行编写的直接 I/O；宿主执行器与进程权限隔离必须一并验收。

模板、资料与变量版本化提示词、角色模板、资料检索端口与类型化变量。按会话、任务和宿主作用域组织。模板和资源版本由宿主固定。外部内容保持来源与不可信标记。敏感变量只保存剪贴板编号和非敏感备注；剪贴板细节仍后续设计。

观测与复测请求/运行/工具关联 ID、延迟、排队、token、预算、错误、脱敏事件、协议语料与契约回放。不记录明文凭证、敏感原生载荷或完整思考内容。未返回的用量标为未知。回放使用 fake 模型和工具结果，不重新操作实际资产。

LLM 访问：基础协议与厂商 PATCH

请求格式与厂商分层。基础协议负责消息、内容块、工具声明、回复、流事件和结束状态。第三方厂商适配器必须继承对应基础协议适配器，复用父适配器的共享行为，只重写经过登记的模型能力和协议差异。GLM 与 DeepSeek 分别使用独立文件；不能把某个厂商的参数分支写满 Agent loop。

Go 没有类继承语法。实现时强制嵌入基础适配器类型，并实现统一 ProtocolAdapter 接口。派生类型直接复用父适配器的共享转换与解析逻辑，只重写允许的差异方法。固定调度器始终通过最外层派生对象的接口调用方法。嵌入不提供虚方法分派，因此基础对象内部不能假定同名方法会自动转到派生对象；共享流程通过明确的扩展接口调用。参见 Go 嵌入与方法提升。

父适配器、派生类型和版本链须登记。准入检查验证真实嵌入结构、父行为复用与重写生效；仅实现同一接口或声明 extends 不算通过。允许重写的扩展点包括 EncodePayload、DecodeEvent、NormalizeResponse、能力描述与错误映射。框架固定执行输入、能力、大小、输出 schema、敏感内容和工具请求校验。PATCH 不能修改鉴权、TLS、端点白名单、脱敏、预算上限、审核、DRY-RUN、SQL 分析或审计。

公共模型类型保留有序内容块和工具关联。厂商续接状态在独立 sidecar 中保存，sidecar 表示与会话绑定的协议附属状态。公共 API 只暴露不透明引用。该状态绑定厂商、模型、协议、版本与会话；不能解码成普通摘要、跨厂商回传或写入观测日志。无法无损表示的协议能力明确禁用。原生状态在受控会话附属存储保存；无法同时满足敏感隔离与有效续接时暂停相关能力。

调用路径为“固定校验 → 选定协议与 PATCH → 编码 → 宿主鉴权传输 → 解码与归一化 → 固定输出校验 → Agent loop”。厂商托管的自动执行工具默认不启用。只有能证明同等审核、预检与审计边界的适配路径才可开放，不能让原生工具在宿主 Harness 之前自行执行。

请求管理与流式处理

一次逻辑请求固定模型配置、上下文快照、协议与 PATCH 版本、工具目录和预算。每次网络尝试另有 attempt ID。请求管理器控制排队、背压、并发、截止时间、取消、响应字节、上下文 token、输出预算和有限重试。统计记录实际选择的配置及估算与实际用量；未知费用或缺失用量不能填成零。

限流和暂时故障采用固定错误分类、退避、抖动与次数上限。参数、鉴权、能力或 schema 错误不自动反复重试。网络取消只能说明本地停止等待，不能证明远端生成或工具已停止。超时后无法确认远端状态时保存未知状态。模型生成重试与工具执行幂等分别管理，不能重放整个 Agent 轮次来修复断流。

流式解码按协议维护事件与内容块索引。工具参数片段只用于缓冲，不派发工具。首版等待完整模型响应终态及完整参数，再执行固定 schema 与目录校验，并送宿主审核。截断 JSON、未知必要事件、块顺序错误、重复冲突 ID 或未完成响应均不能进入执行面。流式文本显示也先经过敏感内容过滤。

模型路由与故障转移仅在宿主固定策略内进行。切换厂商、模型或协议时先检验能力与上下文表示，创建明确的新分支；不转移旧厂商 sidecar，也不丢掉未完成工具对。存在已提交或未知状态的工具申请时先恢复其结果，不能切模型后重做同一操作。

上下文维护、快照与压缩

  1. 上下文管理器固定本轮约束。维护当前目标、最新用户指令、权限与环境引用、模板版本、事实来源与时效。系统约束与工具目录来自宿主，不由模型摘要重写。
  2. 上下文管理器计算输入预算。为输出、思考与工具结果预留空间。按已登记模型使用 token 计数或带余量的估算；不假设所有模型使用同一 tokenizer。超限且无法安全压缩时暂停。
  3. 压缩器只处理允许压缩的历史范围。优先裁剪重复展示与完成历史，再生成结构化摘要或资料引用。保留未完成的工具调用/结果关联。按协议保留或整体处理签名、前缀与续接状态，不能在受绑定的历史中随意挖洞。
  4. 框架检验候选快照。摘要记录原始范围、来源引用、压缩策略及版本、生成配置与未确定项。检验约束、目标、关联完整性、敏感内容和协议可编码性。模型生成摘要时禁用工具，不能借压缩触发资产操作。
  5. SessionStore 按版本提交有效快照。采用版本比较防止覆盖并发新增消息。失败保留上一个有效快照。原始事件按宿主保存与访问策略保留；快照不是唯一审计或事实存储。
  6. Agent loop 使用快照继续本轮。对过期或冲突事实重新查询。摘要中的“已批准”或“已执行”只是描述，执行器仍从独立产物与实际记录核验。恢复与跨模型切换都先重新检验当前上下文及工具状态。

上下文、长期资料、运维事实和执行审计分别保存。资料检索通过宿主端口取得已授权、脱敏且带来源的内容。提示词、日志、文档或工具结果中的指令不能覆盖固定权限。需要服务端压缩或缓存时单独登记其协议状态、存储与数据边界，不能用它替代本地授权记录。

内建与外部注册工具

工具目录支持内建基础工具和外部工具。内建可提供结构化数据处理、内容摘要、已授权资料检索与受限工作区读取；读取实现及权限由宿主提供。Bash、SQL、Docker、云资源和密钥操作由受控平台工具提供。内建与外部只是来源类别，不表示免检级别。

登记清单固定命名空间、名称、版本、输入/输出 schema、实现或远端身份、内容摘要、权限与目标范围、超时与并发、预检能力、影响分类、幂等与恢复条件。可信宿主可以登记已编译 Go 模块、HTTP/RPC 或 MCP 工具适配。远端发现只产生候选清单，管理员审核并固定版本后才能启用。Agent 不能自行登记、更新实现或自动接受动态新增工具。

重复名称拒绝，更新实现或 schema 使用新版本。调用绑定启用时的工具版本和内容摘要。工具提供的“只读”“幂等”等提示须由宿主验证。MCP 工具 schema 与 annotations用于协议描述；annotations 是提示，不能作为权限或安全证明。

  1. GoAgent SDK 整理完整工具候选。仅接受本轮目录中的工具，校验完整参数与调用 ID，绑定会话、运行、工具版本、项目/环境与目标。模型原生 call ID 用于协议关联，不能直接充当执行权限或跨轮次幂等证明。
  2. SDK 提交 GatedToolRequestPort。内建、外部、MCP 与子 Agent 调用均使用该端口。工具实现不作为在 SDK 内任意执行的回调，也不能在注册或构造时提前操作资产。
  3. 宿主 Harness 完成全部检验。独立 JEV 初审、真实预检、产物复核与适用人审。所有 Bash 有有效 DRY-RUN；所有 SQL 按目标产品与版本完整分析。缺任一必需条件均不执行。
  4. 宿主执行器最终核验并执行。核对同一申请内容、目标、scope、工具版本与产物时效。使用持久意图和稳定操作 ID。重复或未知结果先查询实际状态，不能依赖模型重试保证幂等。
  5. SDK 校验受控结果并继续会话。结果先脱敏、限大小并校验 schema，再按原生协议关联到对应调用。并行调用分别审核；有依赖、冲突或未知副作用时不自动并行。失败与缺测保留明确状态。

缺少宿主门禁时，所有命名工具执行关闭，包括内建工具。SDK 自身的编码、预算、上下文维护与事件处理仍可运行。该边界使对话/计划能力可以独立嵌入，又使工具能力只在安全宿主中开放。

平台运维事件单独使用 devops.* 命名空间和平台公共契约：devops.inspection.started/passed/failed 由 Harness 产生；devops.execution.started/completed/failed/unknown 由执行器产生；devops.deployment.state_changed、devops.fact.updated/expired/conflict 和 devops.alert.opened/resolved/delivery_failed 分别由流程、事实与旁路告警服务产生。斜线列出同一前缀下的独立枚举项。passed 只表示对应检验产物通过，执行器仍须最终核验。GoAgent SDK 不依赖平台包；宿主可通过显式桥接器接收这些已核验、脱敏的事件。

外部 HOOKS：事件订阅与 Before 扩展点

Hook 是宿主在指定阶段调用的扩展函数。SDK 公开 HookSpec、HookRegistry、ObserverHook、BeforeHook、HookPoint 和 HookDecision，使其他 Go 系统可编写自己的实现。平台使用同一注册规则。管理员或可信宿主审核实现、版本、内容摘要、订阅范围、输入/返回 schema、顺序、超时、队列和并发上限后登记。重复 HookID 或无法确定的执行顺序拒绝登记。每个运行固定注册表版本；Agent、模型输出和动态远端发现不能自动注册或更新 Hook。

扩展形式公共契约允许的行为
事件订阅 HookObserverHook.Handle(context.Context, Event) error。按 EventType 订阅，异步、有界投递；已有 Observer 继续接收脱敏观测。展示进度、维护宿主的统计、日志与集成投影。读取事件副本，返回错误仅作诊断。After 事实事件没有重写返回值，不能修改 SDK 状态、工具结果或批准结论。
Before HookBeforeHook.Apply(context.Context, HookInput) (HookDecision, error)。仅在下表枚举的候选冻结前调用。按固定顺序串行处理。返回 Continue、Pause、Reject，或有限 Patch。Patch 仅接受声明的非敏感业务标签、已授权资料引用和更严格的业务约束。返回后再次执行固定校验，并生成新的完整候选。不得扩大权限、替换固定指令、改原生签名状态或写入门禁通过标记。
Hook 发起新工作经宿主显式任务入口形成新的 RunID 或受控 ToolRequest，并绑定原因 EventID。不可同步重入当前运行或递归分派事件。自动化建议和工具操作仍经统一申请路径。不得在 Hook 的构造、注册或回调中直接执行 Bash、SQL、云、Docker 或密钥操作。无宿主门禁时，Hook 产生的工具请求同样不执行。
公开 HookPoint检验时点保留的固定规则
before.run.start运行输入齐备后、进入 loop 前。可要求补充业务条件或暂停。宿主身份、权限、目标与运行预算仍由框架检验；不能自行扩大 scope。
before.model.submit候选模型请求形成后、固定版本与发送前。可添加已授权资料引用或业务标签。固定指令、协议状态、工具目录、端点白名单、凭证隔离与预算不可重写。改变候选后重新检验。
before.context.compact压缩候选范围形成后、生成摘要前。可要求保留更多已授权来源或拒绝压缩。必要签名状态、未完成工具对与固定约束仍不可删除；最后通过版本比较提交。
before.tool.request完整工具候选形成后、向 GatedToolRequestPort 提交前。可追加业务限制、暂停或拒绝。工具名称、参数、目标、版本与 scope 不由该 Hook 重写。Hook 的 Continue 不表示批准。固定校验与宿主 Harness/Executor 全部继续执行。

已启用的 Before Hook 报错、超时、panic、返回未知决策或非法 Patch 时，阻断当前阶段。修正 Hook 版本或输入后重新检验，不能用默认 Continue 兜底。事件订阅 Hook 的失败只影响该订阅；调度器记录诊断并按固定阈值停用故障订阅，不改变实际操作结论。必须成功才能继续的业务条件应登记为 Before Hook 或流程步骤，不能依赖观察事件到达。

编译进宿主的 Go Hook 只接纳可信实现。context 取消需要实现配合，超时不证明 goroutine 已停止。超时后的返回不再推进原阶段；仍未退出的回调持续占用并发额度，不无限创建替代回调。外部或不可信实现使用受限独立进程与版本化 RPC，另行实施资源和终止边界。SDK 接口不是任意宿主代码的安全沙箱；资产执行安全仍由宿主权限隔离与执行器强制。

SDK 默认观察事件采用有界内存队列，属于尽力投递，不承诺持久化。满队列时按登记策略合并或丢弃低优先级事件，记录丢弃计数与序号缺口，不无限背压 Agent。需要恢复与重放的宿主接入持久事件适配器；事件与对应状态先在受控存储中保存，再采用至少一次投递，消费者幂等处理。审批、审计、执行意图和检查点的必要保存始终走固定端口，不能依赖可选 Hook 队列。重放通知不能自动重复资产操作。

平台的采集、规则计算、持久告警和通知仍独立运行。SDK Hook 或外部订阅器停机时，监控旁路继续工作。Hook 可以提出后续任务，不能承担核心保活或告警链的唯一通路。平台持久事件适配器中的 SQL 也须按既有规则先完整分析。

扩展准入与 SDK 回归

每个新增协议、模型 profile、厂商派生适配器、压缩器或工具适配器同时提交版本清单与契约语料。厂商适配器须证明继承的父类型与版本、未重写行为沿用父实现、重写通过派生对象分派，且固定门禁未改变。语料覆盖普通与流式回复、分片工具参数、多工具关联、错误、取消、缺失用量、截断、重复与未知字段。协议中的必要状态不可丢弃；未知可选字段只在审核过的 sidecar 结构中保存，不能自动获得执行含义。

上下文复测覆盖并发写入、压缩失败、超预算、固定约束保留、签名前缀、未完成工具对和跨模型分支。工具复测覆盖恶意描述/MCP 注解、版本变化、scope 不足、审核拒绝、无 DRY-RUN、SQL 漏析、断流与执行后崩溃。被拒绝的申请断言不新增执行；尚未提交的无效申请断言执行次数为零。结果不明时断言先查询或暂停。

第二宿主复测 SDK 的协议管理、上下文、外部登记、生命周期和受控工具路径。契约回放只复用记录的脱敏输入、模型事件与受控结果。真实 API 兼容验收在独立获授权环境进行；通过范围写入支持矩阵，不能用 HTTP 请求成功宣称全部协议能力兼容。

事件与 Hook 回归覆盖未知枚举/schema、来源冒充、敏感字段、Before 非法 Patch、阻断决策、候选变更后重新校验、迟到返回、panic/超时、慢消费者、满队列、重复/乱序、恢复和递归。证明 Hook 不能注入审批、绕过 DRY-RUN/SQL 分析或重复资产操作；观察订阅停机不影响监控旁路。公共字符串与 payload 的破坏性变化遵守 SDK 主版本规则，未知事件只作观测诊断，不能产生执行含义。

公共 SDK 先以 v0 开发。P1 就交付第二宿主接入样例，持续检验独立性；P6 通过兼容与恢复验收后发布 v1。按 Go 模块版本规则维护公共 API。破坏性变更使用新的主版本及对应导入路径，不能以平台升级强迫其他系统同步升级。

首版流程与未来编排器

首版状态机只覆盖已定义的项目部署流程。每个运行固定流程版本、步骤、输入、申请和证据。状态至少区分待检验、待审核、待人工输入、可执行、执行中、待确认实际结果、成功、暂停、失败与取消。暂停和故障恢复不自动恢复旧授权。

编排状态在一个持久存储中作为唯一权威来源。状态变更采用版本比较，调度采用有界租约与隔离令牌，重复消息使用稳定幂等键。执行器的实际结果记录独立保存，并由流程核验后推进步骤。超时或网络断开造成未知结果时，流程进入待确认状态；无法确认就保持暂停。补偿是新的受控操作，也先检验再执行。

数据库事务内保存状态和待发送事件，再由有界投递服务发送。此处的 outbox 表示事务内的待发送记录。接收方去重，旧租约持有者不得继续提交。平台升级须保留未完成运行使用的规程、处理器和执行版本；不能仅保留最新两个版本而使长期审批中的任务失去对应执行者。

如果 Temporal 通过 SQL 门禁、部署成本与恢复检验，才可作为新的编排适配器。每个运行只绑定一个编排器。Temporal History 作为该运行的唯一流程状态来源，核心仅保存可重建、带新鲜度的查询投影。迁移在途状态须另行固定方案并检验，不能让两套存储同时推进同一流程。

Temporal 的 Workflow 重放与 Activity 重试不保证外部系统只发生一次副作用。仍由执行器查询实际结果并实施幂等。密钥明文不能进入参数、Signal、结果、错误、心跳或历史，只保存编号和脱敏引用。按 Worker Versioning规则保留所有尚有在途运行的固定 Worker 版本，并检验 Activity 与子流程的跨版本路由。

阶段交付与累积复测

下表是工程开发阶段。每个阶段内部仍遵守“先检验，再执行”。阶段完成不能豁免运行时门禁。阶段验收覆盖本阶段新能力、所有已交付安全关键路径和受影响的旧功能；失败先修复再复测，不以推进下一阶段替代修复。

阶段可交付范围进入下一阶段的条件
P0 · 契约与兼容检验固定模块依赖、协议、公共 SDK 类型、威胁边界与能力矩阵。原型验证真实 DRY-RUN、各 SQL 方言、CGO/双架构构建、持久恢复和候选框架工具路径。固定四种模型协议、厂商 PATCH、上下文压缩、工具目录、公开事件及 Hook 的契约与回归语料。证明不支持的命令与 SQL 被拒绝；展开内容、目标与产物可绑定；SDK 独立依赖可构建。Temporal 内部 SQL 门禁未解决就保持候选禁用。只验证隔离原型，不开放实际资产执行。
P1 · 平台骨架与 SDK v0模块化 Go 控制接口、独立 Worker 协议、GoAgent SDK 的一种基础协议、请求管理、上下文快照、对话与计划、公共事件枚举、ObserverHook/BeforeHook、宿主端口和第二宿主样例。初始复测用 fake 模型、协议语料与隔离存储。第二宿主无需平台服务即可运行；无门禁的工具请求执行次数为零。取消、限额、并发、子 Agent 和脱敏事件通过。第二宿主可按公开枚举实现 Hook；Hook 越权、超时、panic、慢订阅与重复通知均有明确处理。工具分片不提前派发，压缩失败不覆盖有效快照，必要协议状态保持可续接。需要持久化的内部 SQL 已先完成分析准入；未完成则相关存储功能禁用。
P2 · Harness 与执行器完成独立审核、真实 DRY-RUN、完整 SQL 分析、产物复核、危险操作人审、受控执行和独立审计的最小闭环。保存执行意图、幂等键和实际结果。内建、外部注册、Hook 发起及子 Agent 工具共用门禁。在授权隔离环境验证一条受控脚本和一种受支持 SQL 路径。缺产物、过期、错 scope、目标变化、部分分析及审核故障均零执行。进程崩溃后先查结果，重复消息不重复变更。剪贴板仅验证引用边界，详细应用不提前展开。
P3 · 项目流程与恢复项目 Agent 生成、规程登记、限域部署状态机、人工审批和密钥待输入、暂停/取消、步骤补偿、租约与投递。所有步骤共用 P2 执行接口。跨核心/Worker 重启、跨节点恢复、长等待和重复事件通过。旧流程按固定版本继续；新版本不改变在途授权。数据库状态与实际资产结果核对。未知结果停住，未获批准的补偿不运行。
P4 · 一个项目的完整闭环接入一个实际获授权的测试项目，完成 OSS 九步部署、系统服务与受控重启。接入独立监控、告警、CRONTAB 和事实地图。首批仅开放已验收的一个供应商与数据库类型。在实际受控环境按项目要求验收健康、日志、权限、回退和事实新鲜度。关闭 Agent Worker 与核心后，纯指标采集和告警仍继续。JEV/预检不可用时脚本与 SQL 阻断。跨 VM 恢复及单一重启责任通过。
P5 · 多云与派生模块逐产品扩展 Azure、阿里云、腾讯云；逐类型扩展 MySQL、PostgreSQL 派生数据库与自研监控处理器。按接口与组合实现 PATCH。逐项验收四种模型协议及 GLM/DeepSeek 派生适配器；证明父实现复用与重写生效。按 SDK 独立版本交付，不与某云产品绑定。每个新增适配器有独立文件、能力声明、契约测试、失败恢复和版本矩阵。分析不全仍拒绝；冲突、缺测和解析失败不标健康。新处理器回放旧证据不重复告警、不执行修复；门禁逻辑保持固定。
P6 · SDK v1 与发布基线稳定公共 SDK API，完成第二真实宿主接入。交付版本清单、升级/回退流程、支持矩阵、维护责任和运维恢复手册。SDK 最低/当前 Go 版本与既有调用方通过。模型协议、流式、压缩、工具注册、事件/Hook 兼容与故障恢复矩阵通过，支持范围明确。服务协议、数据迁移、旧在途流程、资源限额和恢复通过。已知阻断缺陷为零；功能、测试、观测和文档同时齐备，才发布对应版本。

后续迭代继续按这一套准入条件交付小范围增量。新的宿主、产品、数据库版本或模块类型不能仅靠原有阶段结论自动加入支持矩阵。其新增路径和受影响旧路径必须重新检验。

每次变更gofmt、go vet、相关 go test、受影响并发路径的 race、govulncheck、依赖方向与生成代码一致性。公共 SDK 样例和旧调用方可编译。重放固定模型响应验证确定性路径；模型行为评估另做，不能用模型回答正确代替门禁测试。
每阶段复测累积执行门禁负例、真实目标版本 SQL、事务/租约冲突、审计与凭证隔离、取消和故障恢复。测试在“意图已保存未提交”“远端已成功但本地未记结果”等断点注入崩溃。未知结果与重复投递必须有明确状态。
解析与输入边界针对 SQL 输入、执行申请摘要、JSON/XML/二进制解析和 PATCH 匹配执行 fuzz。每次变更运行种子语料；阶段与发布按固定预算扩展 fuzz。无效、超限、冲突与无法覆盖的输入保持拒绝或未知。
服务与版本兼容在固定版本的真实 PostgreSQL/MySQL、Docker API 及已声明云产品上检验适配器。验证 CGO 目标镜像和 CPU 架构。按支持范围检验新旧 SDK、接口、schema、规程及所有在途流程版本，而不是只检验最新组合。
升级与回退数据库采用“先扩展兼容结构 → 迁移数据 → 最后收缩旧结构”。旧调用方与在途任务退出前不删除旧契约。升级中断、备份恢复、镜像回退和远端实际状态核验分别测试。镜像回退不等于数据库或云操作回滚。
发布门槛已知安全、一致性、公共兼容、审计缺失与恢复缺陷阻断发布。其他已知工程缺口须在功能合入前补齐，或移出本次交付范围并关闭入口。不能用待办、默认放行或失效的测试占位代替实现。

“不留技术债”的工程含义是：不积累已知的设计和实现缺口。每个可用模块同时交付接口、实现、契约测试、失败恢复、资源与观测指标、迁移、文档和版本清单。这不表示未知缺陷永远不会出现；发现后按影响阻断相关能力，补齐复现与回归测试，再恢复发布。

平台、GoAgent SDK、服务协议、流程规程、解析器 schema 和云适配器分别管理版本。发布清单固定其兼容组合。公共模块按 Go 发布流程发布，平台不能通过本地 replace 掩盖 SDK 对外依赖。清晰接口、有限首版范围与自动复测共同支持快速迭代。
